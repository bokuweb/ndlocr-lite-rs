# 分離部品案の追加適用対照

## 追加生成・認識前仕様

最初の新10,944画像では分離部品案の出力変更が0件だった。旧開発例の26件は完全一致へ回復したが、
新対照の非悪化だけでは、案を実際に適用した場合の検証にならない。製品にはまだ接続しない。
既存の画像/truth/条件と全結果は維持し、`docs/detached_body_components.md` の支持条件も変更しない。

追加する本文を `情人` / `情理`、同じ3font file、20/40px、palt=0/1へ固定する。
既知の「情」の部品を別の第2字でも扱えるか確認する適用対照で、未知字形/未知資料のholdoutとは扱わない。
本文2字間ASCII空白0/1/2、closer5種類・先頭/末尾・外側ASCII空白0/1/2、
上下紙0/8px、PNG/JPEG75の8,640画像と、前段と同形式の2,304負例、計10,944画像を保持する。
追加画像を支持条件やNN結果で選別して除外しない。

認識前に原画像と真値を固定し、真値を仮のrawとして実Rust方針へ通す**幾何だけの到達検査**を行う。
これはNN出力や精度測定ではない。基準から新支持へ変更される入力が0なら、NNを実行せず検証不足として記録する。
0件を超える場合は全10,944画像を、元Autoと有効Horizontalの3モデルtensor bit一致後に認識する。
Auto回転例は除外せず、あれば元Horizontal指定も別監査する。モデル/原RGB/実NN入力/commandと終了を保存する。

実際のNN rawによる基準/候補を正式toolのnone/width/strictで全件比較する。
いずれかの群で文字/単語指標に1退行でもあれば採用しない。旧33,735・最初の新32,832組と混同しない。
実NNでの変更がなければ、幾何だけの変更を精度改善や製品接続の根拠に数えない。
この同じ追加対照で接続済み1画素案も別に監査し、元の閾値やtruthを調整しない。

## 最終検証の記録

判定条件を変更せず製品接続まで完了した。全件結果、適用対照の限界、
実NN/API/CLIと再生の区別、再現手順は
[detached-body-components](benchmarks/detached-body-components/README.md) を参照。
凍結時点の先行仕様は同packet内の診断archiveにも保存する。
