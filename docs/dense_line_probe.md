# 横に圧縮された長行のearly-stop診断

## 先行方針

長行固定対照の和文4変形は100文字モデルで2〜8文字となり、80文字の再分割へ入らない。
まず生モデルの候補APIで停止理由と停止時top候補を記録し、sanitizer/低confidence/EOS/
入力の圧縮を分離する。デコーダの閾値や字句を変えて結果を長くする操作はしない。

固定26長短行画像を全件使用する。100モデルの実入力幅高と、各元RGBの幅高、
前景列数/列群数・本文高さ・全幅の生認識/平均confidence/停止理由を保存する。
前景はRGB平均220未満とする。条件を結果ごとに調整しない。

幅高比が100モデル入力比率の2倍を超える横長の入力だけ、既存の安全な
`split_line_for_input` / `crop_line_chunk_rgb_u8` で30/50/100モデルをそれぞれ比較する。
各モデルの実入力寸法を使い、元の画線を消さず、Horizontalを明示する。
chunkの生結果・停止理由と元座標/寸法を全件保存し、既存空白連結規則を使う。
これは入力情報量の診断で、通常CLIの改善と混同しない。真値は推論の選択へ渡さない。

改善が見つかった場合は、別の先行仕様と失敗テストから適用条件を作る。
採用には既存46画像・2検出設定の全276文字指標の非悪化に加え、
新しい対照を先に固定して退行を検査する。局所4例だけから既定化しない。

## 診断結果

4和文は全て `LowConfidence` 停止だった。100モデルの全幅生認識は2/3/3/8文字で、
停止位置のtop確率は0.288/0.129/0.220/0.269。既存停止閾値0.35を下回る。
先頭2文字の平均confidenceが0.931でも、その後の文字が正しく読める保証にはならない。
既存chunkへ同じ元RGBを渡すと、30/50/100の3モデルとも4例の120文字が完全一致した。

26入力全件の寸法、前景、top候補、停止理由、chunk範囲/結果/信頼度は
`docs/benchmarks/dense-line/probe.json` に保存する。
これは全幅ROIの診断であり、DEIM/bandsによるcrop後の復旧成績とは別である。
採用条件と追加の固定対照は `docs/dense_line_recovery.md` を参照。
