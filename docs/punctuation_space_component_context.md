# 句読点後の空白候補を、文字成分の高さで支持する

## 結果: Dを棄却

1,358入力の12,222文字/単語比較は退行0、105本文組の生距離改善、61完全一致回復だった。
大きな独立点の追加360件を含む1,718件でも退行0。ただし新360件での選択変更は0。
横縮尺の新576件を加えた2,294件では、none/widthに18文字・18単語指標の退行が生じた。
9本文組は全て100モデルの横65%で、正読 `案内方法、 連絡先` が空白なしへ変わる。

Dの条件を変更せず棄却し、通常経路から外して基準動作へ一度戻した。
既知ページ8経路6,888比較と単行8経路97,776比較の非悪化でも、この反例を相殺しない。
E/Fを別仕様・認識前固定の共通対照で検査する。

## 別案Dの実装・追加認識前仕様

Cは782入力で12文字/12単語指標の退行があり棄却する。
5本文組は句読点のない実際の語間空白、1本文組は独立点が前景全高を広げた例だった。
Cの画像・真値・判定は変更せず、新しいDを別に評価する。製品接続は評価後の別ステップとする。

- 元のASCII空白の直前が `、` / `。`、直後が前段の仮名/漢字範囲の場合だけ調べる。
  これは語間一般を削る処理とはせず、句読点の字形余白を同モデルで確認するための条件。
  非空白6〜12文字・元の内部ASCII空白1つ・その他は前段と同じ文字範囲、
  3候補一致・各confidence .98〜1・上下0px候補が元より厳密に高い条件は維持する。
  返すのはモデル候補そのものとし、文字列の推測置換はしない。
- 画素支持は既存の `visible_repetitions` の8近傍collectorをそのまま読み取り利用する。
  RGB和660未満、area>=3の成分の最大bbox高をHとし、area>=max(3,ceil(H/2))を残す。
  残った成分bboxのx区間の和集合から内部最大白列幅Gを測り、`0 < 4G <= 3H`を要求する。
  collectorのcount gate・bbox・area処理を変更しない。計測と記録はまずtest-onlyに置く。
- 画像全体の高さは使わず、純白余白と分離した小点で支持が強まらないことを例示/PBTで検査する。
  点が大きい/接続する場合に無条件の不変性は仮定しない。不正RGB/全白/白列なしは拒否する。
- Cの782入力と全候補をSHA検証で再利用し、新たな576入力を認識前に固定する。
  文は `受付番地`＋句読点＋`通知先` / `開催日時`＋句読点＋`集合場所`。
  句読点 `、` / `。`、直後のASCII空白0/1/2個、前段3字体＋AppleMyungjo Regular、
  24/40px、PNG/JPEG75、上下追加0/10px/10pxと独立点の3文脈の全組合せ
  （2×2×3×4×2×2×3=576）。描画bboxの周囲2pxを保持する。
- 各fontで必要な非空白文字のmaskが未収録文字のmaskと異なることと、ASCII空白の送り幅が正であることを
  描画前に確認し、font SHAを固定する。空のmask同士になる場合を空白の未収録と誤判定しない。
  点のx座標は描画した元画像の最大内部白列群の中央（同幅は左、なければwidth/2）とし、
  yは紙追加後の0とheight-1とする。字形本体・真値は変更しない。
- 保存後にdecodeした元RGBと、左右2px/上下0・1・2pxの3候補を別bboxでHorizontal認識する。
  atlas内の各bboxが1chunkであること、元RGBと追加純白の保持、binary/source/model SHAを検査する。
- 1,358入力×3モデル×3正規化の12,222文字/単語指標を公式scorerで全件比較する。
  退行が1件でもあればDを棄却する。新対照の後で条件・真値を変更せず、合計改善で相殺しない。
- Dを製品へ接続する場合は、callbackと容量/方向/失敗/候補不一致のRedを先行し、
  raw/候補API・全単行/ページ経路・実CLI・3モデルの設定互換を比較する。
  これらを通す前に採用済みとは扱わない。未知実資料・速度への一般化も仮定しない。
