# 分割した行の白余白とモデル誤読の切り分け

同じ固定PARSeqへ渡した原寸chunkで、引用符欠落と余分な数字が発生する。
画像の全画線は残っている。正解と元ページはomoの凍結評価に由来し、開発データとして扱う。
まず生出力の完全一致をRedにし、モデル入力の白余白に対する感度を測る。

採用できる処理は画線を削らず、白余白のみを一般的な寸法条件で扱うものに限る。
正解文字列・文書名・モデルconfidenceによる候補の選択は行わない。
推論前に正解を固定した別PDFのアポストロフィは現行版で正しく、対照として維持する。
記事の未調整続頁も初回推論前に正解を固定し、全文で比較する。
既存和文・混在・句読点・数字の全文評価が悪化する処理は採用しない。

`crop_rgb_u8_tight_horizontal` は通常のbbox検証後、RGB全チャンネルが255の
外側の列だけを除去する。254や色画素、内部空白、上下余白は保持する。
白紙は元の非空cropを返す。推論回数と画素の値は変えない。
`crop_line_chunk_rgb_u8` は両端が単語境界または行端である分割chunkに限って適用する。
未分割行と字形間で分割したchunkの文脈は保持する。分割情報の判定もライブラリ内で行う。
全分割chunkへの適用は和文2ページ目106→111/863、Rust5→6/357、領域6→7/588と
悪化したため棄却した。採用条件はこれらの全文・領域の上限を維持すること。
単語境界に限定しても和文2ページ目は111/863だった。また、余白を除いた画像は一般に
公式PARSeqの `5*height > 4*width` の回転条件を跨ぎうるため、回転方向が変わる
切り出しは元の余白を保持する。等号は回転しない境界としてテストする。

回転方向の保持だけでも和文2ページ目は111/863だった。短い単語chunkでは
入力全幅へ拡大することで字形の文脈が変化するため、調整対象を保守的分割上限
`MAX_CHUNK_ASPECT=8` から一字高以内の幅（`width >= 7*height`）に限定する。
これは開発コーパスで検証する幾何ヒューリスティックであり、未知文書での改善保証ではない。
短いchunkは元の余白を保ち、回転方向の保護も引き続き適用する。

長さだけの条件も句読点ページ100→105/627となり棄却した。記号が疎なchunkで
拡大率が大きく変わるため、少なくともインク列群上限の半数（10群）がある場合だけ
白余白を除く。RGB254も列群として数え、少数画線の文脈を保持する。
この支持数の9/10境界をRedにしてから実装し、全文コーパスを再検証する。

最終採用条件の全文評価は英語記事30→24/2269、関連続頁25/2307を維持。
金融75/473、和文142/836・106/863、Rust5/357、混在31/326、句読点100/627、
領域6/588・0/117・9/91、色ヘッダー2/17も従来の編集距離を維持した。
全画線保持PBT、支持数9/10・幅6h/7h・回転等号の境界、および原寸3cropの実PARSeqを検証する。
推論回数は不変。走査とfallback再切り出しの追加コストは未計測。

その後のCode欠落調査では、幅5h/非白列群9へ対象を広げる候補で全文の差し引き改善を確認した。
現行条件と棄却試行・行単位の悪化は `docs/chunk_word_omission.md` を参照する。
