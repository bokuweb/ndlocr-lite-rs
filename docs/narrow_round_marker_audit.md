# 幅の狭い丸括弧の行形状を調べる

## 監査実装前仕様

比較元は1ec730a。現在の支持は幅ceil(本文高/4)未満のmarkを拒否する。
既知の `)情報` には幅4px・本文高20pxのmarkがあり、この境界は前段でも意図的に保持した。
今回は採用条件を緩めず、元画素の行別形状を監査して次の仮説を立てられるか確認する。
新NNや製品接続、語句置換は行わない。

- 入力は既存の `narrow_round_prefix_mincho20.png` と対照の `info_corner_mincho20.png`。
  元RGB/SHA/寸法を保持し、元collectorと同じRGB和660・8近傍・面積floorを診断上で再計算する。
  このPython監査を実Rust collectorの再測定やOCR精度比較とは扱わない。
- 各成分のbbox/面積と、bbox内の行別x座標/連続区間数を保存する。
  行画素数の和が成分面積に一致し、全所属画素を一度ずつ数え、元RGBを変更しないことを検証する。
- 8近傍接続と小点の除外、既知4px幅・本文高20pxをテストで先行する。
  narrowとcornerの全記録を保持し、都合のよい行だけを選ばない。
- 新しい支持仮説が得られた場合も、別途仕様・純粋Red・全保存raw比較と新NN対照を固定してから検討する。
  本監査だけで安全性・非悪化・未知字形への汎化を主張しない。
