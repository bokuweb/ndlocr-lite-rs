# 縦列の複合画線を幅支持で保護する候補

## 実装・新画像・追加NN前の仕様

prefix延長候補e5b11b4は、新36本文の5原RGBで字形内部の白帯を境界に選んだため、
候補全体をNN前に棄却した。既存retain_glyph_boundariesは、6個以上の全幅支持から得る
中央値以内の群を保護するが、隣接2群がともに細長い画線である場合だけを扱っている。
今回はその字種を特定するルールを足さず、幅支持のある複合群の幾何だけを検査する。
棄却済みprefix候補を復活させず、まず既存縦列分割の境界修正を独立に評価する。

### 固定仮説

test-onlyの別実装で、現行のanchor数6・anchor閾値2/5・幅中央値・列高上限・累積群幅制約を
そのまま使い、内部白帯を除く際の「両側とも細長い画線」という必要条件だけを除く。
中央値以下の同じ幅包絡に収まる隣接群を結合し、包絡を超えれば必ず境界を残す。
支持が足りなければ元の白帯を保持する。20群/幅制約、元RGB、分割探索、空白の扱いは変えない。
字種、GT、font/PID、行番号、句読点や辞書を選択条件に使わない。
製品splitterと既存Hは、事前検査を通過するまで元のbyteを保持する。
別sourceコピーのテスト内だけで仮説を実装し、通常worktreeの製品関数は変更しない。

### 先行テストと対照

- 小さいRed→Greenで、幅包絡内の複合群、中央値外の群、支持5/6の境界、長い細線の連鎖制限、
  外側の字間保持を検査する。拡大/移動/反転/配色を含む64例PBTを追加する。
- 前段の全114原RGBと342形状組を既知回帰として残す。NNは未実行だが幾何を観測済みなので、
  新規幾何holdoutとして数えない。前段の全24切断イベントも固定した回帰とする。
- 未生成の6本文を43/53/67/79/107/131 scalarへ固定し、既知3書体×余白2条件の36原RGBを
  作る。本文は固定段落の先頭N scalarとし、GT/glyph bbox/font/SHAを推論前に固定する。
  新旧PNG/RGB SHA未重複と独立のglyph mask再描画を検査する。既知fontの開発対照である。
- 全150RGB×3形状について元幅/半幅の両分割を検査する。新旧の全注釈付き本文72画像の
  字形内部を1件でも切れば候補全体をNN前に棄却し、画像ごとのGT採否は行わない。
  原RGB chunk/余白/図形/分割失敗をすべて保存する。
  明示縦列の元RGB支持とHのOtsu支持の両方を検査し、認識用chunkは常に元RGBに戻す。
  大きな復元コピーを作らずに検査できるよう、元RGB chunkはZIPでlossless保存してよい。

### NNと製品採否（幾何gate通過後のみ）

同じ凍結3モデルと元画素で、従来分割と候補分割の明示Vertical経路を全150入力で比較する。
元幅の既存分割が対象で、半幅分割は幾何対照のままとする。原AutoやPageの結果と混同しない。
新96画像のNN結果はまだ存在しない。前段の保存raw54×3は再利用であり、新NNに数えない。
API呼出し/モデルload/内部forwardは別々に記録し、計測しないforward数を推定しない。

全入力別none/width/strict文字・単語指標に退行がなく、負例の出力が安定し、少なくとも
1個の新規RGBで改善することを必須とする。分割失敗やNN失敗も残し、平均だけで採用しない。
製品接続前には既存293ページと既知縦書き7ページ、新対照について実API/CLI A/B、
明示縦列の既存完全一致回帰、Hの採用/棄却/native一致、通常/ONNXの必要検査を行う。
いずれかで条件を満たさなければ接続せず、失敗と全対照を保存する。

## 結果: 幾何gate未達のため候補全体を棄却

通常worktreeの全製品source/Cargoをbyte不変に保った別コピーで、3失敗/3成功のRedから
6成功へ進めた。64例PBTを含む。未使用になった画線判定だけをrefactorで除去した後も、
default library406件、既存の縦組み幾何33件（7/2/4/20）はすべて成功した。

新36RGBは旧index/fixtureの313,512 SHA値と未重複で、2,874個の非白glyphについて
draw.textと独立getmask配置の全byte一致を確認した。新旧全150RGB・注釈72画像を結果で除外せず、
3形状×元RGB/Otsu×元幅/半幅の1,800組を、従来分割と候補の双方で記録した。
追加モデルload/Session.run/認識APIは0回である。

| 指標 | 従来 | 候補 |
| --- | ---: | ---: |
| 字形内部の切断イベント（両chunk端） | 116 | 36 |
| model/preparation/budget/glyph単位 | 58 | 18 |
| 切断のある原RGB | 16 | 7 |
| 分割エラー | 210 | 210 |
| 元RGB chunk | 6,003 | 5,971 |

境界変更は135/1,800組、新たな分割エラー0、エラー解消0。
合計11,974 chunkをlossless ZIPへ保存し、独立PIL CCW回転/cropと全byte一致した。
3表・5,400 CSV行と両variantの切断イベントも独立に再計算した。
イベント減少は幾何の観測であり、OCR精度の改善とは数えない。

7原RGBに切断が残るため、先行固定した全件gateに従い候補全体を追加NN前に棄却した。
元の条件を緩めたり、GTで画像を除外した認識比較はしていない。mainの製品sourceは不変である。
全画像/GT/source/Red/Green/ZIP/失敗と独立監査は`tmp/vertical-composite-capacity/`へ保存した。
後続候補と公開する場合も、この棄却結果を保持する。

残る10個のimage/preparation条件では支持成分の幅中央値39〜43に対して、切断されたglyphの
縦包絡は41〜46だった。幅中央値は字形全体を覆う上限にはならない。同じ支持成分が直接隣接する
区間の中心間距離中央値は51.5〜52であった。これは既知fontの診断値で、固定pixel値として使わない。
次は、直接隣接する全幅支持の送り幅から包絡を推定する別仮説を、先行仕様と未認識対照で調べる。
