# PARSeq の縮小方式を比較する診断

## 実装前の仕様

細い記号が補間時の参照位置から外れる可能性を調べる。製品の前処理・公開APIは変更しない。
実験用 example は横書きに限定し、同じ RGB・モデル・文字集合を二方式へ渡す。

- 対照は既存の浮動小数点 bilinear/BGR/NCHW 前処理。
- 候補は縮小する軸だけ画素の被覆面積で平均する。拡大する軸は既存と同じ中心座標の線形補間。
- RGB の整数丸め、余白追加、分割変更、後補正、正解を用いた候補選択をしない。
- 面積重みと積算は f64、最後の正規化後に f32 とする。
- 幅・高さゼロ、RGB長不一致、寸法積の overflow を確保前に拒否する。
- 細線の平均、分数境界、色順、恒等変換、拡大、濃度保存の PBT を先に固定する。

比較例は truth を読まない。既存の背景正規化・行分割・crop・空白挿入を共用し、各 chunk の本文・信頼度・寸法と時間を保存する。
モデルの実入力寸法を ONNX から読み、CPU 1 thread/Level3 の同一 session で両方式を交互に推論する。
出力には既存方式も全件保存する。失敗した候補も報告し、出力先の上書きを拒否する。

omo 側で、推論より先に既知14画像・新規合成記号対照・既知の記号欠落3帯と採用条件を凍結する。
各既知画像の文字・行誤りが増えず、完全正読対照と AI 句を保持し、合成対照の誤り総数が減ることを採用条件とする。
14画像は既知の開発用コーパス、合成画像は人工対照であり、未知の実文書 holdout の代用にはしない。
この診断の実行だけでは製品設定を変更しない。
