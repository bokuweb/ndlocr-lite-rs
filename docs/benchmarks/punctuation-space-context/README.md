# 句読点の誤空白と原RGB文脈

比較元は `9fc4528d0da24f076fd19edc1adc6b4cd7b2a970`。採用候補Fは、
短い日本語本文の句読点直後に生じたASCII空白1個を、同じ供給モデルによる
3つの実認識結果で確認する。原画素は変更せず、純白の余白だけを加える。
単純な削除や文書語句の置換は行わず、実際の先頭候補の本文とconfidenceを返す。

## 候補を読む前に固定した条件

- 空白を除く本文は6〜12文字、日本語と `、。` に限定し、空白は句読点と本文の間の1個だけ。
- 元Autoが横書きになる寸法で、左右各2pxの追加後も供給モデルのnative縦横比内に収まること。
- RGB合計660未満の8近傍成分を既存の面積閾値で抽出する。
  本文高H、成分の水平被覆幅S、最大内部空白列G、空白を除く文字数Nについて
  `0 < 4G <= 3H && 4GN <= 3S` を要求する。
- 左右各2px・上下各0/1/2pxの全候補が元本文から空白1個だけを除いた文字列に一致し、
  confidenceが有限かつ0.98以上。先頭候補は元confidenceを厳密に上回ること。
  不一致・エラー時は元結果を保持し、追加forwardは最大3回。
- raw/候補APIとNNデコーダは保持する。同じSessionを再使用し、追加モデルは読み込まない。

初期仕様は各archiveのcapture-spec/sourceに保存する。結果追記後のdocsを
実行前の仕様と取り違えないこと。製品接続仕様は
[punctuation_space_advance_integration.md](../../punctuation_space_advance_integration.md)。

## 開発診断と反例

全て固定フォントや既知ページの開発回帰であり、未知の実資料holdoutではない。
各段階の入力は次段階に累積するため、画像数や正規化別指標を独立標本として合算しない。
正解・画素・閾値は各段階の認識前に固定する。

| 候補/段階 | 累積入力 | 文字/単語それぞれの比較数 | 退行 | 結果 |
| --- | ---: | ---: | --- | --- |
| C: 紙を除いた前景高 | 782 | 7,038 | 各12指標 | 実空白と孤立点の6組で失敗、棄却 |
| D: 面積で絞った成分高と句読点境界 | 1,358 | 12,222 | 0 | 次の対照で継続検査 |
| N: 大きな点/線ノイズ | 1,718 | 15,462 | 0 | 新360入力では選択0、追加改善と数えない |
| AS: 横方向だけの縮尺 | 2,294 | 20,646 | 各18指標 | 100モデル・横65%の実空白9組を消し、Dを棄却 |
| E: 2番目に広い本文成分の幅 | 3,446 | 31,014 | 0 | 82組の文字距離改善、56完全一致回復 |
| F: 水平被覆幅/文字数 | 3,446 | 31,014 | 0 | 114組の文字距離改善、70完全一致回復 |

E/Fは既存2,294入力だけで決めず、新しい2文・3書体・2サイズ・4横縮尺・
4紙/ノイズ条件・PNG/JPEG・空白0/1/2個の共通1,152入力を加えて比較した。
Fの114改善はモデル30/50/100で48/10/56組、完全一致は34/4/32組。
残る誤字のある改善も区別し、114全てを正読回復とは数えない。

ASの初回exportでは30モデルの14 ROIが分割され、whole ROIという契約に反したため
採点しなかった。全初回出力を保存したうえで `--whole-roi` を明示したexporterを作り、
全2,304 ROI×3モデルを再実行した。元から単一区間だった6,898記録は全候補/確率まで一致した。
初回14入力も残して全件を採点する。E/Fでも全4,608 ROIの実forward直前RGBと寸法を検証した。

## 製品経路の検証範囲

3,446入力×3モデルの保存済み実NN結果をRustの製品選択関数へ渡し、
callbackの画素・寸法・順序・回数、元画像不変、通常単行/断片の両sanitizerを検査した。
62,028文字/単語指標の退行0。これは製品選択の全件replayであり、全経路の新規NN実行ではない。

Fが選択した全100入力IDと、Dの失敗例・pin・層別の実空白負例を合わせた158入力を、
基準版/F版、30/50/100モデル、rawを含む8経路で新規認識した。
全7,584本文/confidence記録はreplayと一致し、11,376文字/単語指標の退行0。
供給3モデルのbatch dimensionは全てstaticで、batch APIも同じ単画像NN経路となることを
実Session metadataで確認した。別途、混在bucketの順序、raw/候補API、
エラー後再利用、初回ロード後のモデル削除も実モデルテストで検査する。

単行CLIは前後計14プロセスで、3モデルの正例3組を完全一致へ回復し、
実空白と縮小反例の4組を保持した。stdoutから除くのは末尾LFを厳密に1個だけ。
ページ出力ファイルの改行は加工しない。

Fの287画像×8ページ経路は全件新規実行し、SHAを検証した基準版参照と比較した。
6,888文字/単語指標の退行0。30の評価/既定設定の丸字体24px半縮小1画像で
生/width文字距離1→0、単語距離2→0となり、他2,294本文組はbyte同一。
API全1,722組の行数・3,460行のbboxが不変で、confidence変更もこの2組だけ。
実CLI574本文は全byte同一だった。通常639件・ONNX実モデル556件・example23件成功、
Clippyの新規警告0。丸字体36px側の誤空白などは残り、改善施策の検討を継続する。

`native.zip` / `page.zip` は棄却したDの途中監査であり、Fの新規認識に数えない。
Fの実API/ページ検証は `validation.zip` に分離する。
仕様・TDDログと、認識前に凍結したsource/binary/model/charset/input SHAを保存する。
モデル・font・実行binaryは同梱しない。取得元/権利情報は各data/attribution内に保持する。
追加推論の速度と未知資料での汎化は未確認。

## 再現

モデル不要、Python標準ライブラリだけで実行できる。保存NN値と独立した成分探索から
選択を再計算し、公式 `eval_ocr_metrics.py` のCSV/Markdownと監査を比較する。
archive SHA・全member SHA・重複alias・入力RGB/正解SHAも検証する。

```bash
python3 docs/benchmarks/punctuation-space-context/reproduce.py tmp/punctuation-context-replayed
```

作成先は存在しないディレクトリを指定する。`--raw-only` はC〜Fと製品選択replayまで。
全実行は528ファイル（264 CSV・264 Markdown）のbyte一致を検査する。
新規NN測定を再実行する場合は、各archiveの凍結sourceとコマンド/環境/モデルSHAを使う。
現在のsourceで過去候補を上書き測定しないこと。

| archive | 内容 |
| --- | --- |
| raw | C/Dの全画像・RGB・NN候補・選択と先行A/B参照 |
| noise | 大きな点/線ノイズの追加360入力 |
| aspect | 横縮尺の追加576入力、初回分割とwhole ROIの再測定 |
| advance | E/F共通の追加1,152入力、両選択とRust製品replay |
| native | 棄却Dの1,358入力×3モデル×8経路の前後実測 |
| page | 棄却Dの287入力×8経路の前後実測/参照 |
| validation | 採用Fの158入力×8単行経路と287入力×8ページ経路の監査 |
