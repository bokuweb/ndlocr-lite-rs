# Latin追加対照の保存Auto/Horizontal比較

## 採点・実装前の仕様

latin-pair-bridge段階の追加19,440条件のうち、canvas比率でAuto回転した
636元画像を全件扱う。同じ元RGBに対する保存済みAutoとHorizontalのrawを、
全3モデル・none/width/strictの文字/単語距離で比較する。追加NNは行わない。
これは既知の横組み・既知fontの開発対照で、方向識別の汎化評価ではない。

- 前段のpairing検査（ID一意・欠落/余分拒否・寸法・真値SHA・元RGB SHA・
  Auto回転条件・両forward寸法）を継承し、順序に依存せず本文をstripしない。
- 実際の元RGB/真値/原画像のSHAも検査する。元RGBから90度反時計回りに
  並べ替えたbytesが保存Auto有効RGBに一致し、Horizontal有効RGBは元と同一で
  あることを、テスト先行で検査する。不正寸法/長さ/向き/画素差を拒否する。
- 636条件を全て採点し、textとnoiseを別にも集計する。noiseのbody-only真値は
  前段と同じ診断上の規約で、curve/forkの意味を一意な非文字と扱わない。
- 全体/両群について入力別の改善・同点・退行・完全一致回復/喪失を保存する。
  異なる方向で一方だけが正読する例も残す。モデル・重複条件を独立標本と数えない。
- 元画像/出力/仕様/scorer/driverのSHA、正式CSV/MDと反例を保存し、前段packetを
  SHAで参照してモデル不要で再現できるようにする。

本監査から一律Horizontalや新しい方向判定を製品へ接続しない。以前の192画像には
strict退行があるため、次の候補には真縦組み・短文・紙/枠/ノイズを含む新対照を
認識前に固定し、RGB前処理と後処理の方向契約を合わせた検証が必要である。
