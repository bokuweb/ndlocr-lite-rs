# 縦列の出力上限付近のprefixを二分割で確認する候補

## 実装・生成画像・追加NN前の仕様

停止理由監査447532bでは、30文字出力+最後のEOSは本文にも余白/図形にも見られた。
上限付近という条件だけでは区別しない。Hのcount<=16/group40/4倍/0.9/空白列条件は変更しない。
別のtest-only候補として、元raw全文をprefixとして保持し、異なる二つの安全な分割が
追加する全文に完全一致するときだけ、末尾を延長できるかを検査する。
製品のPage/Pool/Sessionの挙動はこの段階では変えない。

### 固定する候補条件

- 出力metadataのclassとcharsetが一致し、固定T>=3が分かる場合のみ扱う。入力幅からTを推定しない。
  原rawのscalar数はT-1またはT。元認識が失敗した場合は元のエラーを保持する。
- Autoと同じ縦回転範囲、原幅>=12、長さはモデル入力の2倍を厳密に超える。
  寸法/積/RGB長不一致、奇数または0のモデル幅/高さ、動的Tは候補なし。
- 元RGBを既存の無補間CCW回転へ渡す。支持用だけ有理数Otsuを使い、認識へは元RGBを渡す。
  支持インク列は全幅1/3以上、字高支持は全高1/2以上を要求する。
- 既存split_rotated_vertical_column_for_inputへ、元の入力幅と半分の入力幅を渡して二つの
  境界集合を作る。認識モデル自体は変えない。各分割2chunk以上かつ境界集合が異なることを必須とする。
  二・三の内部白帯保護と、空白を足さず元順に結合する既存の規則を保つ。
- すべてのchunkは空白のみでなく、finiteの0.9..1 confidence、raw scalar数1..T未満を要求する。
  両分割の結合文字列が完全一致し、元raw全文をbyte完全一致のprefixとして含み、1 scalar以上長く、
  異なるalphanumericが4種類以上あるときだけ候補を返す。Unicode空白scalar列も元rawと完全一致させる。
  confidenceは第一分割だけのscalar加重f64平均をf32へ戻す。二分割を独立標本として数えない。
- 候補の失敗/不一致/不支持は元rawを保持する。GT、語彙、book/font/PID、行番号を選択へ渡さない。

### 先行テストと未認識対照

既知54入力すべてを回帰へ残す。元rawは停止監査の保存結果をそのまま再利用し、追加NNと混同しない。
新しい6本文を31/35/47/51/63/103 scalarへ先行固定し、既知3書体・左右上下余白2条件で36原RGBを生成する。
本文は各固定段落の先頭N scalarを使い、推論後に変更しない。GT/実glyph bbox/font SHAを固定する。
3背景×zigzag/brush/cross/ladder×35/65群の24図形RGBも先に固定し、診断上のGTは空文字とする。
全60原RGBが旧評価のPNG/RGB SHAと重複しないことを確認し、全文/図形を結果で除外しない。
同じ既知fontの合成開発対照であり、独立holdoutや学習未使用資料とは主張しない。

候補はstub Redから、小さい幾何/原RGB保持/異分割合意/prefix/空白/平均/失敗のテストと
64例PBTを先行して実装する。新60画像のbaseline180 API呼出しと、全114入力×3モデルの
候補判定に必要なchunk呼出しを追加NN前の同じ固定条件で記録する。
原画像の全glyph bboxが分割境界で切断されていないことを、NN前に独立に検査する。
glyph bboxは検査だけに使い、認識や入力ごとの採否へ渡さない。新36画像の1件でも切断があれば
候補全体の事前geometry gate失敗として保存し、追加NNを行わない。GTで入力だけを除外した
採点はしない。画像や境界を結果に合わせて直さない。

### 採否

候補の採用は、全入力別none/width/strictの文字・単語指標が非悪化、余白/図形の出力安定、
GT空白/句読点/元prefix不変、少なくとも1新規RGBの改善を必須とする。平均値だけで判断しない。
実装採用前には既存293ページ・追加既知縦書き7ページと新対照の全入力で実API/CLIの前後比較、
native Red→Green、通常/ONNXの必要スイートと既存警告との差分を再確認する。
退行/無改善なら候補を製品へ接続せず、その結果と全失敗を保存する。

## 事前geometry gateの結果: 候補全体を棄却

純粋テストは結合stubの2失敗/1成功→3成功、幾何stubの2失敗/4成功→6成功へ進めた。
64例PBT、異分割の元RGB保持、失敗時の部分出力拒否も含む。
新36本文/24図形は、公開indexとfixture575ファイルの312,538個のSHAと未重複だった。
PNG decodeとraw RGBも全60で一致し、GT/glyph bbox/font/paddingをNN前に固定した。

全114RGB×3形状の342組を、T-1個のdummy ASCIIで文字数gateだけ開いた幾何検査へ渡した。
151組で二分割を作れたが、これは実rawに対する候補到達数ではない。
生成した1,151chunkは独立PIL CCW回転/cropと全byte一致した。
元glyph bboxの内部を切る境界が5原RGB・12個のmodel/route/glyph位置にあった。
隣り合う両chunk端を数えたイベント数は24（30/50形状それぞれ12）である。
「え・遠・品・前」の離れた画線などで起き、既存の二・三保護だけでは十分でなかった。
この文字名は原因調査の注記だけで、製品ルールや採否条件には使わない。

先行固定した全件gateに失敗したため、候補全体を追加NN前に棄却した。
新画像baseline API、chunk API、モデルload、Session.runはすべて0回。
結果で画像を除外した評価や、同じ候補の閾値/境界の調整はしていない。
test-only prototypeは証拠として保持し、Page/Pool/Sessionへ接続しない。
default library全400成功/35ignored、新規Clippy警告0。

全入力/GT、境界、元RGB chunk、source、Red/Green/失敗を公開パケットへ保存する。
復元後の独立監査は342行CSV、1,151chunkの画素一致、24 cutイベントの一致を再現し、
モデルやNNを使わない。分割境界の一般的な修正は別の先行仕様・新規対照で扱う。
