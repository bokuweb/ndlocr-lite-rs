# 画線幅とモデルが読んだ文字数による空白支持F

## 診断結果

E/Fの仕様と実Rust geometryを新規認識前に固定し、全4,608 ROI×3モデルの13,824 forwardを共用した。
全て各1chunkで、認識直前の4,608 RGBを原画素/追加純白およびSHAと比較した。

Fは全3,446件・31,014文字/単語比較で退行0、生距離改善114本文組、完全一致回復70組。
新1,152件では30モデル4組が完全一致へ回復し、それ以外の本文は変わらなかった。
実selectorと単行/断片sanitizerを通した固定実NN値のRust内replayでも、62,028文字/単語比較は退行0。
これは全件NNの新規再実行ではない。実API/実CLI/ページの接続検証は別仕様で行う。

## 実装・新対照の認識前仕様

Dは横縮尺対照で棄却。Eは既存2,294入力で退行0、78本文組の生距離改善だったが、
連結した字形では幅anchorがなくなり、既知のページ回復例も見送る。
連結成分を単文字とみなさず、モデルが既に読んだ非空白文字数を幅の基準にするFを別に検査する。
EとFは共に未採用。Eの条件・既存データ/全結果は変更しない。

- Dと同じ8近傍collectorの保持成分から、H・内部最大白列G・左右の最初/最後の画線を得る。
  最後のx+1から最初のxを引いた画線全幅をSとする。画像の外側白紙はSに含めない。
  collector・RGB閾値・成分除外を変更せず、単文字への分割や文字数の画像推定はしない。
- 元デコードから内部ASCII空白1個を除いたUnicode scalar数N（6〜12）を用いる。
  候補が同じ非空白本文であること・句読点境界・confidence/3候補一致など、Dの条件はそのまま。
- 支持は `0 < 4G <= 3H` と `4GN <= 3S` を両方満たす場合だけ。
  Dの採用集合を広げず、Fの幅側の式は紙の位置と整数の横縮尺に不変とする。
  全支持についてはH側の制限も残るので、任意の横伸長/連結変化の不変性は主張しない。
- 不正RGB・全白はNone。白列0・Nが6〜12外なら非支持。
  比較はu128で行い、Nを乗算前に検証する。
  例示でDが支持する幅不足の空白、幅側の閉境界、Nの範囲を検査する。
  PBTで白紙/灰度/整数横縮尺とNを変えてS/Gの比例、幅側の不変性、Dへの包含を検査する。
- E仕様で認識前固定した1,152入力（新2文、22/36px、4横縮尺、紙/上端点/中央点）を、
  まだモデル認識していない共通対照としてEとFの両案へ使う。
  新しいモデル出力を見る前に両案の条件を固定し、同じraw/3余白候補を3モデルで一度ずつ取得する。
  `--whole-roi`、RGB/単一区間、source/model/binary SHAの条件はEと同じ。
- 既存2,294入力をSHA検証で再利用し、両案それぞれ全3,446×3×3=31,014文字/単語指標を比較する。
  退行があればその案を棄却する。新対照を見て式や真値を変更せず、合計改善で相殺しない。
  通った案も、callback・全公開API・実CLI/ページの接続比較を終えるまで製品採用としない。

本文を推測置換せず、返すのは同じモデルが返した候補そのもの。
未知実資料や混在文字幅の一般化、速度改善は仮定しない。
