# 隣接する全幅支持の送り幅による縦列境界の保護

## 実装・新画像・追加NN前の仕様

幅包絡だけを使った前段候補は、切断116→36イベントへ減ったが全件gateを満たさず棄却した。
残るimage/preparation10条件では、成分幅の中央値39〜43よりも字形全体の包絡41〜46の方が長かった。
字形の一部しかつながらない列で、つながった成分幅を字形全体の上限とする仮定を見直す。
診断値51.5〜52を固定pixel値にせず、元画像の直接隣接する支持成分から送り幅を推定する。
前段の閾値を変更して成功扱いにせず、別候補として仕様・全結果を保持する。

### 固定する幾何

- anchorは現行と同じ幅/横包絡とも列高の2/5以上、最低6個とする。
  原成分幅の上側中央値を基準幅とし、累積群の幅を追う。
- 間に別成分を挟まない直接隣接したanchor対だけについて、中心間距離を採る。
  2倍距離は`左成分幅+2*白帯幅+右成分幅`。離れたanchorを飛び越えて対にしない。
  少なくとも6対あるとき、2倍距離の上側中央値を2でceilし、候補の送り幅とする。
  加算overflowはその標本を使わず、最低支持に満たなければ基準幅へ戻る。
- 拡張包絡は`min(列高, max(基準幅, 支持送り幅))`。支持送り幅が不明なら基準幅を使う。
  基準幅以内の群は前段と同じように保護する。それを超えて拡張包絡以内の群は、
  既存is_tall_narrow_stroke_pairがfalseの場合だけ保護する。両側とも細長い独立画線なら、
  推定送り幅だけで境界を消さない。字間の揺れで別の細線を一群に吸収し続けないためである。
- 群が包絡を超えれば境界を残して累積幅をリセットする。20群/幅・分割探索・空白規則、
  元RGB保持・既存Otsuの意味は変えない。字種/GT/font/PID/行番号を条件に使わない。
  未使用になったという理由で削除した旧画線判定は、この候補では元の定義のまま使う。
- 通常worktreeの製品sourceを保った別コピーで先行検査し、採用条件を満たすまで製品へ接続しない。

### 先行テストと未生成対照

基準幅内の既存6テストを残し、送り幅で救える複合群、隣接対5/6の境界、別成分を飛び越える
誤推定の拒否、列高上限、包絡超過の連鎖停止、揺れる字間での独立細線維持を小さいRed→Greenで
検査する。拡大・移動・反転・配色を含む64例PBTを加える。

前段の全150RGBを既知幾何回帰へ残す。新6本文を41/59/71/83/109/137 scalarへ先に固定し、
既知3書体×余白2条件の36原RGBを作る。送り幅は各glyphで52±3の固定周期とし、
単純な等間隔だけを新対照にしない。段落先頭N scalarのGT・glyph bbox・font/SHAと周期を
推論前に固定する。3背景×2図形×2群数の新12図形も異なる周期で作り、診断上のGTは空とする。
新48RGBは既存公開index/fixtureと未重複であることを確認し、独立getmask配置も検査する。
既知fontの合成開発対照であり、独立資料holdoutや学習未使用とは主張しない。

全198RGB×3形状×元RGB/Otsu×元幅/半幅の2,376幾何組を対象とする。
前段の従来分割1,800組は元150RGB/SHA・製品関数が同一な場合だけ再利用してよい。
新48RGBの従来分割576組と合成し、入力を重複/欠落させない。再利用を新しい実行として数えない。
候補は全2,376組を実行し、原RGB chunkと失敗をlosslessで保存する。
新旧の注釈付き本文108原RGBの字形内部を1件でも切れば候補全体をNN前に棄却する。
GTで入力ごとの採否を選ばず、分割エラーも従来と対応させて検査する。

### NNと採否（幾何gate通過後のみ）

同じ凍結3モデルで、全198画像の従来/候補の明示縦列経路を比較する。元幅の分割を使い、
認識へは常に元RGB chunkをraw Horizontalで渡す。紙の変更や方向再推定を加えない。
半幅とOtsuは幾何対照のままとし、Hの実際の経路は別のnative/API検査で確認する。
過去のraw Auto54×3はchunked baselineの代用にせず、比較参考として保持する。
新NN数は実際のAPI呼出しと分けて記録し、内部forward数を計測なしに推定しない。

NN前の収録・採点規約: 各model内のbyteと寸法が同一のchunkだけは1回のraw候補API（Horizontal、top_k=1）を
両variantへ共有してよい。共有を独立NN実行とは数えず、全元画像/分割/部分RGBとの対応を残す。
全step/stop/平均f32 bits・全失敗を保存し、追加推論前にユニークchunk/RGB/SHA・呼出し総数を固定する。
結合は元順のraw本文の連結のみで、空白や改行をtrimしない。診断用confidenceは第一層chunkの
Unicode scalar加重f64平均をf32へ戻す。GTや平均confidenceで入力を選別しない。
分割/NN失敗はerrorとnull本文のまま保存し、部分出力を完成本文として使わない。
公式採点用の全198ファイルだけは失敗の本文を空proxyとして出し、文字脱落として計数する。
proxyであることを全行のstatusへ明記し、成功した認識や正しい空白とは数えない。
全件表に加え両側成功の対照表も示し、新たな失敗/失敗の隠蔽を認めない。

全入力別none/width/strictの文字・単語指標を示す。退行がなく、負例の出力が安定し、
少なくとも1個の新しいRGBで認識が改善することを採用条件とする。
製品接続前には既存293ページ・既知縦書き7ページ・新対照のAPI/CLI A/B、既存の明示縦列完全一致、
Hの採用/棄却/native一致、通常/ONNXの必要スイートを確認する。
失敗や無改善なら接続せず、前段の棄却結果と全source/原画像/GT/raw/失敗をまとめて保存する。

## 結果: 幾何gate通過、認識gate未達のため不採用

別コピーで新6テストの4失敗/2成功から、前段6テストを含む12成功へ進めた。
2つの64例PBTを含む。default library412件/36ignoredと既存縦組み幾何33件も成功した。
新48RGB（字間変動本文36・図形12）をNN前に固定し、全198RGB/注釈108本文を収録した。

従来2,376幾何組は旧1,800組と新576組を、元source/150RGB/SHA一致を確認して合成した。
候補は2,376組を新規実行した。従来124→候補0のglyph切断イベント、新たな分割エラー0、
分割エラー総数234→234。元RGB chunk8,794+8,578=17,372個は、独立PIL CCW回転/cropと
全byte一致した。これは幾何の結果で、OCR精度を示す値ではない。

比較元の初回driverでは、実行中にNN採点規約を仕様へ追記してしまい、仕様1ファイルだけの
SHA不一致を検知した。全失敗データ/旧仕様/ログをgeometry-historyへ保存し、同じコードと入力を
仕様固定後に再収録した。二回目は全source/入力不変を確認した。新NNはこの履歴の間も0回だった。

全198画像×3モデル×2variantの1,188本文に必要なraw RGB/寸法を先に固定した。
同一model内だけで重複を共有し、各732・計2,196 raw候補APIをHorizontal/top_k=1で実行した。

2,196組のRGB/寸法・UTF-8 range・確率bits・停止条件・f32逐次平均を独立に照合した。

Red3失敗→Green3成功を先行した。
