# 短い行の字形保持

## 先に固定する仕様

幅2482pxの文書で「目次」「（目的）」は各行のインクが少ない。
従来の `max(width/80,8)` を全ての画素行へ要求すると、横線の多い数行だけが閾値を超え、
字形が高さ7px未満の断片となって除外される。認識前の欠落なので文字補正では解決しない。

- 強い画素行の閾値は従来の `max(width/80,8)` を維持する。
- 少なくとも8インク画素ある弱い行を、最大2画素行の空白を挟んで同一候補にする。
- 候補内に強い行が少なくとも1つあり、高さが7px以上なら全候補を保持する。
- 強い行のない弱いノイズ、7px未満の孤立断片は除外する。
- 3行以上の空白を跨いで別の行へ接続しない。末尾の空白は候補の高さへ含めない。
- naive/fast経路の結果と座標を一致させる。文字列置換を追加しない。

## 回帰と限界

合成の弱い字形＋強いseed、ノイズ、2/3行間境界、下端を含むPBTを先に追加する。
公開文書の原寸cropを幅2482pxの白いcanvasへ配置し、元座標で目的・目次の字形が全高で検出されることを確認する。
実ONNXでは全角括弧の誤りを正解から消さず、目次の本文復元と既存3 corpusの誤り上限を確認する。
この方式も幅閾値を一度も超えない極小文字や、罫線/写真のseedの判別は保証しない。
読み順・段組み・縦書きと全ページCERは別の評価が必要。

## 実施結果

実装前は合成/実画像/PBTの4テストが失敗し、omoの全ページ実推論も「目次」の欠落で失敗した。
実装後は目的を `(目的)`（全角括弧2誤り）、目次を `目次` として復元する。
全ページでも両見出しを元の領域・43px以上の字形高で認識する。
通常152件、短い行の実ONNX対象6件、omo実ONNX/表構成110件を確認した。
omoの既存corpusは描画6/588、スキャン0/117、別文書9/91を維持する。
全ページには別の誤りや欠落が残るため、全文の精度向上量はまだ主張しない。
