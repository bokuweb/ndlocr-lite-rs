# 点付きLatin判定の製品接続仕様

## 実装前

既存223,143組と追加59,322組の固定候補はnone/width/strictの入力別文字・単語距離で
退行0。追加freshの変更64組と元Horizontalの変更26組はすべてtextで、noise変更0。
この結果を条件変更に利用せず、凍結したowner/policyを最後の構造判定へ接続する。

- 既存の方向・寸法・閉じ括弧・文字数のgateをそのまま通す。文字内容の置換は行わない。
- Agjpの先頭丸括弧PNGを公開Session/Horizontal Pool、3モデルで先にRedにする。
  rawは`)Agjp`、処理後も同じ本文を要求する。raw/処理後mean bit、元RGBの一致も検査する。
- 1つの呼出しのみ追加してGreenにする。所有と判定の凍結SHAを保つ。
- 全282,465保存組で製品出力と事前固定候補の一致を実Rustで検査する。
- 変更全件と事前固定324noise対照を実API/CLIへ通し、本文・raw・meanを検査する。
  CLIの末尾LFを正確に1個だけ除く。新raw取得/API検証/CLIは別計数とする。
- model30で実際に取得した19,774 NN入力RGBを全件effective画像と照合する。
  3モデル入力tensorの事前一致証拠も保つ。

既知の3書体・同じ生成系内の開発用対照であり、未知書体/資料への汎化やページ精度向上とは
区別する。Model/方向/重複RGBを独立標本として数えない。
