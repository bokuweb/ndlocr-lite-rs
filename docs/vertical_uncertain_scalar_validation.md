# Nの一文字訂正分岐を別の新規対照で検査する

## 追加N2検査: 新画像・追加NN前の仕様

固定Nは342画像/3モデルで、実Fragmentの単件・batch・専有batchを含めて退行0だった。
13改善組の内訳を調べると、完全prefixを保つ延長が9組、一文字訂正を伴う延長が4組だった。
Nで新規生成した72画像の7改善はすべて前者だった。一文字訂正の効果は提案時に既知だった4組だけである。
Nの条件を変更せず、訂正分岐も新規の位置・字サイズ・本文で検査してから採用を判断する。

### 維持するもの

- Nのplan、原RGB、metadataのT/C、H優先、二分割合意、末尾空白除外を保つ。
- 元winnerの0.9未満、両分割の訂正文字winnerの0.98以上、全chunk平均0.9以上、
  一文字だけのalphanumeric置換、その他prefix保存・厳密延長・空白列一致を保つ。
- 実装・モデル・charset・前処理・decoderを変えず、Nの全342入力も比較から除かない。
  真値、文字そのもの、書体、ファイル名、描画時の文字位置を採否条件に使わない。

### 描画前に固定する対照

新しい3段落を、実metadataの各T-1/T/T+4 scalarへ切り出す。
既知3font file×余白0/8で54本文とし、字サイズ36px、送り40px、原幅44px＋左右余白とする。
既知の複雑な漢字や数の画線を含めるが、既存の全文や文字位置は再利用しない。
段落・切り出したGT・全font SHA・配置・生成sourceを描画前に固定する。
既知字形・既知fontの開発上のストレス対照であり、未知資料や学習未使用のholdoutとは扱わない。

3背景×2図形×各T+2群の18非文字対照も固定する。幅44px、送り42pxを基準に、
固定した小さい送り変動を使う。診断用の真値は空とし、NN前に規約を記録する。
新72RGBは旧342RGBとSHAで重複させない。PNGdecode/RGBと字形配置の別描画を照合し、
非重複glyph bboxを保存する。合計414RGB、字形注釈270本文となる。

### 実行順と採否

1. 新72入力で元RGB/Otsu・主/副span・3モデルの幾何を先に検査する。
   旧342の記録は同じsplitter/source/RGBであることを照合した場合だけ再利用する。
   注釈した字形内部の切断があれば追加NN前に検査全体を棄却する。
2. 新Auto72×3を測定する。旧Auto1,026と旧Horizontalは、同じmodel/charset/source/RGB/寸法/方向の
   実記録だけを再利用する。新規NN対象と採否条件を追加認識前に固定し、GTを入力へ渡さない。
3. 全414×3modelのN採否を実Rustで再生し、literal範囲・停止・確率bits・mean bitsを別実装で確認する。
   完全prefix延長と一文字訂正の改善・退行・適用0を分けて記録する。
4. 入力別none/width/strict文字・語の退行0、非文字出力変更0、新旧の完全文54対照への誤変更0を必要とする。
   N2新規RGBで一文字訂正分岐による改善が少なくとも1件なければ、その分岐の新規有効性は未確認とする。
   N全体の採用は保留し、条件を後から緩めて通したことにはしない。
5. 通過時には新72の実Fragment/他経路も変更前と比較し、旧342結果は同じ最終runtime sourceのものだけ再利用する。
   293ページ・既知縦書き7ページ・新対照のAPI/CLI、必要suite、公開再現packet/CIも完了させる。

失敗や無改善も全件保存する。前の342入力だけを通過した事実を、新規の訂正分岐の検証へ置き換えない。
モデルload、画像API、内部forwardは区別し、未測定の内部forward数はnullとする。
