# 本文より小さい中央フッターを検出する

## 実装前の仕様

開発ページの頁番号は24px高で、本文の文字高約46pxに対して小さく、
row投影にも全高成分の条件にも届かない。文字列「1」の挿入や置換は行わず、
欠けている画素を認識器へ渡す。

既存の小文字高seedの寸法・密度・面積条件は維持する。本文左端との整列に加え、
ページ中央のフッターという幾何条件をもう一つの文脈として許可する。

- 既存行が2本以上ある場合だけ、その字高中央値を利用する。
- 最後の既存行より下の未検出領域に限る。
- 成分中心がページ中央から本文字高の1/2以内にある。
- 直前の本文下端から字高の2倍以上離れ、ページ下端から字高以上離れる。
- 点、細線、塗り潰しを排除する既存の高さ・縦横比・密度条件を変更しない。
- フッターは本文と異なる小さい書体なので、本文字高まで上下余白を広げない。
  元の成分高に上下1pxだけ加え、幅は高さの5/4以上として自動回転を避ける。
  左端整列の小文字は従来どおり本文字高の余白を利用する。
- 本文やヘッダー内の小図形を新たな条件で昇格させない。

原寸の頁番号crop、両検出経路、平行移動PBT、領域外とノイズの負例を先に追加する。
固定PARSeqで原文 `1` と比較し、omoの全文と既存corpusで回帰を確認する。
幾何だけでは中央の図形と文字の完全な区別はできない。左右フッターや小さい字の
任意の行は対象外とし、この開発資料から未知文書の精度は主張しない。

## 認識上の限界

当初の完全一致期待 `1` は未達。元高の26px切り出しでも本文字高の余白でも、
固定モデルは `11` を返した。16種類の横書き余白の診断では `1` と `11` が混在し、
特定の幅/高さへ合わせる変更は採用しない。幾何検出の回復とモデルの正読を分け、
テストでは画素被覆・検出数と現行モデルの誤読をそれぞれ記録する。
omoの厳密な原文は `1` のまま維持し、当初期待138/836に対する139/836の失敗も記録する。
欠落の2編集（改行+1）が1編集（余分な1）へ減る限定的な改善である。
