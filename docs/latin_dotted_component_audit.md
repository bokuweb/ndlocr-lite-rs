# 上点kernelの保存画素への読み取り専用適用

## 抽出実装・計測前の仕様

11テスト/PBTを通過したowner関数をkernel-lock.jsonで固定する。製品callerと追加NNは0。
この段階は本文/marker policyではなく、点とstemの幾何対応の監査である。

- latin-pair-bridgeの223,143保存結果から、rawが空白なしASCII英字3〜8字と端のround closer
  1個で、本文に小文字i/jがある全行を選ぶ。raw正読だけに絞らず、全corpus/モデル/方向を保持する。
  元RGB SHAで重複をまとめ、全参照ID/本文/真値/製品前後/寸法/方向を残す。
- RGBの和660未満を前景とし、既存take_regionによる8近傍連結成分を全て回収する。
  既存collectorの面積filterを変更せず、診断だけの別readerを使う。1/2画素の島も捨てない。
  寸法0/長さ不一致/overflowと65,536画素超を拒否し、白画像は空の成分集合とする。
  全成分の面積和が元前景数に一致し、成分のbbox/面積は独立Python抽出と全件一致することを要求する。
- 上記readerに先行するRed/Greenで8近傍・独立島・白画像・不正RGBを検査する。
- 幾何監査では各参照の先頭/末尾に応じてx順の端成分をmarker仮説として外す。
  残りの最大成分高Hを使い、全残り成分を順に点候補とし、他の成分をstem候補にする。
  これは真のmarker/文字境界の認定ではない。marker仮説もdot候補も結果から選び直さない。
- 成立/不成立・全成分・H・唯一の所有stem・参照文字列を保存する。全元RGBの寸法/SHAを
  実行前後で確認し、source/実行ファイル/入力と終了記録を保存する。

点が付いたことを文字保持や精度回復と数えない。次のpolicyではi/jとの位置対応、markerの実画線、
全前景の所有、本文の高さ/間隔、実空白・外側ノイズを別途検査し、追加対照の認識前に条件を固定する。
