# 紙余白に依存しない生空白候補の画像支持

## 実装・追加認識前の仕様

比較元は9fc4528。前段A/Bは棄却済みで変更しない。
ここでは全画像高を使ったBを、220閾値の前景y最小/最大による画線高へ置き換えるCを検査する。
まず診断/純粋テストとして作り、下記の全件条件を満たすまでは製品へ接続しない。

- RGB長と幅/高さの積を検証する。3チャンネル和660未満を前景とし、前景全体の高さと、
  左右の外側白列を除いた内部完全白列群の最大幅を測る。不正寸法/長さ・空画像はNone。
  前景があるが内部白列がなければ最大幅0とする。
- 幾何支持は `0 < 4 * max_blank_gap <= 3 * foreground_height`。
  倍率・位置・純白外周余白で判定が変わらないことを例示/PBTで検査する。
  659/660境界、全白、不正RGB、内部白列なしと実空白の反例も固定する。
- 本文とconfidenceの条件は前段A/Bと同じ。内部ASCII空白1つ・その他は前段と同じ仮名/漢字/和文句読点、
  非空白6〜12文字で、3余白候補すべてが元の非空白文字列に一致し、各confidenceが有限の.98〜1、
  左右2px/上下0px候補のconfidenceが元より厳密に高い場合だけ、その実モデル候補を選ぶ。
  語句置換や手作業の空白削除は加えない。
- 前段302入力の画像/真値/全候補をarchive/member SHAで確認して再利用する。
  測定は各atlasの元bboxのRGBそのものをlossless PNG/RGBへ取り出し、JPEG再decodeの差を混ぜない。
  Rust測定の実binary/sourceも追加認識前に凍結する。
- 新規480入力を追加認識前に固定する。文は `検査結果、担当課` / `登録内容、保存先`。
  読点後の空白0/1/2個、読点前の空白1個、読点を空白1個へ替えた語間の5形式。
  前段3字体×20/32px×PNG/JPEG75×紙文脈4種類の全比較（2×5×3×2×2×4=480）。
  元の描画bbox周囲は2px。
- 紙文脈は上下追加0/4/12px、上下12pxに独立した黒1px点を2つ加えたもの。
  点は(2,0)と(width-3,height-1)。字体本体や真値は変更しない。
  PNG/JPEGを保存後に読み戻したRGBを固定し、左右2px/上下0・1・2pxの3候補も原画素を保って作る。
  各bboxは別々にHorizontalで入力し、各1chunkを要求する。
- 782入力×3モデル×3正規化の7,038文字/単語指標を公式scorerで画像別に比較する。
  1件でも退行すればCを棄却する。合計改善や最初の302件だけで採用しない。
  新対照の結果を見て条件・真値を調整せず、別案が必要なら別仕様を先行する。
- Cを採用する場合は、raw/候補APIを保つcallback方式の失敗テストを先行し、全単行/ページ経路・
  models30/50/100・confidence/RGB/エラー再利用と実CLIを比較する。追加モデルを勝手にロードせず、
  失敗時は元結果を保持する。接続検証を終える前に製品採用済みとは扱わない。
- 固定fontの開発診断を含み、未知実資料への一般化・速度の改善とは扱わない。


## 固定782入力の測定結果（Cを棄却）

新規480入力×4画素条件×3モデルの5,760認識を実行し、全1,920区間が各1chunkであることを確認した。
前段302入力の906本文組はarchive/member/RGB SHAを確認して再利用した。
全782×3×3=7,038文字/単語指標のうち、none/widthで12文字・12単語の退行があった。
これは6本文組の正読から誤り1への退行で、正しい語間空白5組と独立点のある読点後空白1組。
strictはASCII空白を除くため、この退行を検出しない。

生距離の改善97組（うち完全一致回復53組）に対し退行6組。
合計改善で相殺せず、仕様どおりCを棄却し、製品の認識経路へ追加しない。
例えば `登録内容 保存先` / `検査結果 担当課` の実空白をモデル合意が消してしまう。
独立点の例 `登録内容、 保存先` はconfidence約.99697の正読が約.99917の誤読へ変わる。
点により前景高60px・内部白列34pxとなり、文字本体以外が画像支持を強めていた。

これらは開発用固定フォント対照であり、未知実資料の性能や速度を示さない。
次のDは別仕様・追加対照で評価し、Cの画像/真値/選択結果と実行前仕様は保持する。
