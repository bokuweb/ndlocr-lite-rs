# 検出枠が覆わない横書き行を、同じprimaryモデルの全体文脈で確認する

## 実装前仕様

比較元270f85a（製品sourceはbae38d3と同一）。先行診断では、全文枠のない混合英数字の
既定APIが断片だけで30モデル13誤り/100モデル9誤りとなり、同モデルの原画像は各4誤りだった。
confidenceの固定.9では100の.893を除外する。一方、全体候補の一律置換は高confidenceでも退行する。
`docs/missing_line_context_probe.md` の未被覆画線を使う層を、全287画像・CLIでも実測する。

既存の全認識、confidence/空文字フィルタ、包含断片整理の後でのみ確認する。
非空かつ有限0〜1の平均confidenceを持つ元結果があり、非空白文字数で重み付けした平均が
0より大きい場合に限る。元bboxは正・画像内とする。
元RGBの220前景が元bbox和集合の外に残り、既存の横書き帯検出がちょうど1本を返し、
帯が幅/高さ5/4以上で、既存の文字画素支持を満たす場合だけ候補を作る。

候補は原画像全体とその帯cropの順。重複bboxは1回だけ。
候補内に全220前景が含まれ、実際に渡すRGBの比率が供給primaryモデルのnative比率以内であることを要求する。
元RGBを変更せず、同じprimaryのHorizontalで追加認識する。APIは供給parseq pool、CLIは既にロードした
primary poolを使い、新しいモデルはロードしない。CLIの既存cascade各行とprimaryのconfidence比較も
全件で検査し、通過を仮定しない。

新候補は非空・有限0〜1で、元結果の平均confidenceを厳密に上回るものだけを選ぶ。
合格候補間もconfidence最大、同点は先の候補を保持する。原文/辞書/真値で選ばず、文字を置換しない。
採用時は候補bbox/text/confidenceの1行に置く。追加確認の失敗/不一致時は元の出力を保持する。
元の検出/認識のエラー、options、raw/単行API、外部辞書/ルールpackは従来どおりとする。
追加確認は外部辞書適用前に行う。帯がない/複数/図形、画線欠落なし、native超過には追加推論しない。

先に純粋方針の未実装Red、画素保存・confidence境界/失敗・全被覆/白紙/図形/2行/native/不正入力とPBTを固定する。
実モデルで既定APIの混合A1 JPEGの欠落をRed化してから接続し、CLI両構造設定も確認する。
採用には全287×6×3=5166ページ文字指標非悪化と全単語指標記録を要求する。
単行は呼出経路を変えないが、認識source SHAと固定263×3の保存予測を照合し、新規byte一致も確認する。
前後の全結果・追加呼出/対象・source/binary/model/input SHAと途中の退行を保存する。
追加推論のため高速化は主張しない。
