# 通常行の字形高で孤立した短い末尾行を補助検出する

## 実装前の仕様

全ページ幅2482pxでは末尾の「う。」は最大row ink14でseed31へ届かない。
「う」の上部と本体も離れており、row密度の閾値だけを下げるとノイズや別行を拾う。
既存の通常行を変更せず、未検出の縦領域だけを8近傍の画素成分で調べる。

- 既存行が2本以上ある時だけ、その字形高の中央値を基準にする。
- 高さが基準の2/3〜3/2、幅が高さの1/4〜3倍、面積が高さの2倍以上、
  密度が8〜65%の成分を文字候補seedとする。小点、細い罫線、塗り潰し矩形をseedにしない。
- seedと近接する上部字形および同じ基線付近の句読点を含める。
  付属成分にも密度80%以下と文字高に基づく寸法上限を要求する。上部字形はx範囲が重なるものだけを含める。
  隣の行や離れた点へ接続せず、最終高も基準の3/4〜3/2に収める。
- 同じ基線の複数seedは境界を合併し、後続字形を捨てない。
- 既存の行境界とは交差せず、通常行の分割や認識文字列を変更しない。
- 未検出領域内の成分数が256を超えたら補助検出を中止し、ノイズで二乗処理を増やさない。
- naive/fastで補助検出の座標を一致させる。

先に原寸の「う。」cropを2本の通常行と同じcanvasへ置く回帰、合成の孤立字形、
小点・細線・塗り潰し・離れた句読点・上下行分離の試験を追加する。
実ONNXで「う。」を認識し、omoの全文CERと既存corpusを比較する。
この開発fixtureだけでは写真・任意のノイズ・縦書きの検出品質は保証できない。

## 確認結果

実装前に原寸の末尾行が欠落する2試験が失敗した。実装後は「う。」を固定PARSeqで復元する。
近接する塗り潰しの誤取り込み、同じ行の後続seedの欠落も別のRedで再現して修正した。
平行移動32ケースのPBT、ノイズ成分上限、既存の短い見出しとの両経路の一致を確認する。
omoの開発ページは156→153/836誤り（厳密Unicode、空白・改行を含む）、既存corpusは維持した。
頁番号「1」はまだ欠落する。数字の密度・字形条件や、実スキャンでのノイズ評価は残る。
