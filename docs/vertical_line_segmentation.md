# 明示指定の縦書き列検出

## 呼出側の長い列の分割（追加仕様）

`rotate_vertical_column_rgb_u8` は既知の縦書き列を無補間で反時計回り90度回転する。
寸法比にかかわらず回し、入力RGB長さ・非空寸法・積overflowを確保前に検査し、確保失敗をErrで返す。
上→下の文字順を左→右へ移し、RGB成分は保持する。既存Autoが回す縦長列では、回転後Horizontalの入力テンソルと完全一致する。
呼出側は回転後に縦列用の白列分割とHorizontal推論を使える。長い列を一度の推論へ押し込まず、分割失敗は本文を部分返却せずエラーとする。
検出矩形は引き続き元画像の座標を保持する。短い列も明示縦書きとして回すため、自動方向推定は追加しない。

## 仕様（実装・初回推論より前に固定）

- 既存の横書きAPIとomoの既定動作は変えない。縦書きであることが既知のページ向けに `pipeline::vertical_segment::detect_vertical_textline_columns` を追加する。
- RGB8の寸法・長さ・積のoverflowを検証し、不正入力はResult::Err。空画像もエラーにする。
- 検出座標系のみ転置し、既存行検出を再利用する。列末右側の句読点が転置後の行末下側に対応する。返す半開矩形は元画像の絶対座標、右から左の列順。推論時のcropは元画素で、PARSeqのAuto前処理を使う。
- 明るい紙面の陰影補正は呼出側の明示操作。縦書き自動判定、混在レイアウト、複数段、傾き、ルビは対象外。
- 初回推論前に固定した公式縦書き画像の原文・6列・右→左順をfixtureにする。source.jsonで画像と原文hashを保持し、XMLを正解扱いしない。
- Redでは現在の横書き検出を仮実装に使い、正規化後の6列検出と元座標を再現できないことを確認する。Green後に実ONNXで同じ画像の横書き経路より厳密編集距離が改善することを検証する。先行固定原文と出力の空白/句読点/改行は正規化しない。
- 合成矩形で右→左順・元座標・白紙・不正寸法を検証し、拡大/移動のPBTで変換の境界を確認する。

## 評価の限界

この画像は公開upstreamの開発サンプルで、学習時の重複は否定できない。全文の完全一致、未知資料、実写真、低解像度、縦横混在、omo→DOCXの縦書き再現は別の受入条件。紙の陰影補正も本番の既定にはしない。

## Red → Green の判断

横書き経路ではraw 81/83編集、陰影補正後は安全な空白境界で分割できずエラー。初回の反時計回り回転では6列・9/83編集まで改善したが、右側に離れた句点が検出用座標の上側へ移り欠落した。目視句点と合成輪郭句点をRedにし、検出だけ転置する方式へ変更した。PARSeqへ渡す元画素を転置・鏡像化する処理ではない。

テスト用矩形の初回期待値には既存 `refine_x_bounds` の2px余白を1pxと誤記したため、元座標の列方向に2px、列幅方向に1pxへ修正した。列数・順序・原文・句読点範囲は変更していない。

追加コストは検出時にRGB8画像1枚分（3×width×height byte）の一時領域と転置走査。既存の横書き経路は変更しない。速度の優位性は未計測。

## Windows checkoutの原文固定

Windows CIではGitのautocrlfにより原文LFがCRLFへ変換され、列数6は一致するが83文字の期待が89文字となって失敗した。原文と評価器で改行を除去・正規化するのではなく、このfixtureだけを `.gitattributes` の `text eol=lf` で固定する。元の原文hash・83文字ゲート・生出力は変えない。autocrlf=trueでのcheckoutでもLFだけが残ることを検証する。

## 回転済み縦列の分割（実装前の追加仕様）

横書きの単語間隔推定は回転した縦書き字形に適用しない。`split_rotated_vertical_column_for_input` は白列だけで分割し、区間間へ空白を追加しない。短い列の文脈を保持するため、最大20インク列群、幅/高さ比20以下かつモデル入力比の2倍以下の区間にまとめる。これは30文字PARSeq向けの保守的な開発上限であり、全資料・全モデルの精度保証ではない。限界を超える列は既存の白列境界探索で均等に分割し、区切れないものは拒否する。横書き分割の挙動は変更しない。

## 長い列の内部白帯（2026-10-17、修正前の仕様）

固定した31字の列では均等分割の中心にある「三」「二」の内部白帯が選ばれ、
実モデルがそれぞれ「三一」「一一」と認識した。通常31/34/36字の3列と「一」の対照は全文一致した。
`tests/fixtures/long_vertical/manifest.json` の6画像・原文・画素hashを先行固定し、
字形矩形は分割検証の正解にのみ用い、分割・推論には渡さない。

均等目標近傍の最大白帯を選ぶ初案は、20インク列群の制限で三の後ろの字間が候補に入らず、
描画回帰が引き続き失敗したため不採用。

修正方針は縦列専用の白帯分類とする。前後のインク列群がそれぞれ列幅の1/10以下の細さで、
縦方向の広がりが列幅の2/5以上あり、白帯込みの合計幅が列幅の2/3以下の場合、
その白帯を一字内の画線間とみなし候補から除く。20列群制限はこの結合後のインク群へ適用し、
幅/高さ比20・モデル入力比2倍の制限を維持する。残る境界は既存の均等選択を使う。
短い列の無分割、連続被覆、空白非挿入、分割不能エラーは維持する。
横書きの分類・境界選択は変えない。追加推論や文字置換、原文による位置選択は行わない。

Redでは二/三の字形内部での切断と全文不一致を確認し、Greenでは6列すべて全文一致、
既存短列4/83以下、横書き実モデル回帰の維持を要求する。等間隔字形の拡大・移動でも境界と被覆を検証する。
これは開発画像に対する局所的な境界選択であり、この幾何条件が常に一字を示す保証はない。
同じ画素に見える字形内外の間隔、詰め組み、ルビ、未知写真、独立holdoutは別の評価が必要。

### 連鎖結合の追加ガード（追加修正前）

二本の画線の条件だけでは、密な細線列が連鎖して無制限に一群になる。
太さ・広がりが列幅の2/5以上ある独立群が6個以上ある場合に限って内部白帯の除外を行う。
さらに結合済み群の全幅も列幅の2/3以下へ制限する。細線だけの曖昧な列は従来の20群分割を維持し、
支持字形を付けた長い細線列でも連鎖を有界にする。全文の数字列を常に正しく区切る保証ではない。
