# 分割行の単語欠落と白余白の比較

後続の小余白保持条件は [chunk_context_margin.md](chunk_context_margin.md) を参照。

## 仕様（実装前）

横書き行の一部をPARSeqへ渡すと、その区間にない下伸び字形のために確保した
上下余白まで縮小される。記事続頁の `the Code of` は画線が残るのに
`the of` と認識される。EOSまでの復号に変えても同じだったが、純白の上下余白を
除いた同一画素では `the Code of` になった。モデル・文字集合・復号は変更しない。

追加する垂直切り出しは、指定領域の全RGB成分が255の外側行だけを除く。
非白画素（254や色画素を含む）、左右余白、内部の白行、画素値を保持する。
白紙は元領域を返す。入力検証は通常のcropと同じ。

行chunkへの適用は複数区間の行だけとし、PARSeqの回転条件を跨ぐ場合は
元の上下余白を保持する。まずこの最小条件を開発コーパス全体で評価する。
既存の和文・英文・領域評価を悪化させる場合は採用せず、試行結果を残す。
認識済み文字列への置換、複数推論による結果選択は行わない。

## 全区間試行の棄却と次の条件

全区間への適用は記事1が24→36、金融75→78、和文1が142→143、混在31→37、
句読点100→119、領域6→8と悪化した。単独cropの成功だけで採用しない。
次に、白余白が高さの1/5以上で、非白行の外接高さが元高さの2/3以上の区間だけを
評価する。微小な余白と孤立小記号の大きな余白を保持するための幾何条件である。
条件境界を単体テストで固定し、未知データへの保証として扱わない。

中間帯だけの試行でも記事1が24→33、記事2が25→26と悪化したため棄却した。
次は非白外接高さの条件を維持しつつ、少ない側と同量の純白を反対側にも残す。
上下の均等な余白を除かず、非対称な余剰だけを除く。回転判定は余白を残した後の高さで行う。
原寸cropでは上1/下10を上1/下1にした場合も `the Code of` を認識できた。

上下均等化でも記事1が24→30、記事2が25→24となり、既定動作には採用しない。
横方向だけを x=8..239 に詰めた原寸246×46のcropは、上下46画素を保持したまま
`the Code of` を認識できた。次は既存の横余白処理の対象を幅/高さ比5以上、
独立インク列群9以上へ広げる候補を評価する。単語境界・回転保持・純白限定の条件は維持する。
これは開発データに基づく候補であり、全コーパスの悪化があれば棄却する。

## 採用する動作

垂直切り出しの試作は除去した。既存の横方向cropのみを使用し、対象を幅/高さ比5以上、
非白列群9以上へ広げる。単語境界・回転不変・全非白画素/内部空白/上下寸法の保持は維持する。
幅79/80（高さ16）、支持数8/9の等号境界をRed→Greenで固定した。
`chunk_word_omission_tests` は原寸の9列群chunkで生出力 `the Code of` を固定する。

公開基準4bf567eに対する開発全文の編集距離は、記事1 24→22/2269、
記事2 25→22/2307、和文1 142→140/836、句読点100→96/627。
記事2のCode欠落は復元する一方、別行の `to C/C++` は `toC/C+++` へ悪化する。
各行が一様に改善する変更ではなく、全文の差し引きで採否を判断した。
金融75/473、和文2 106/863、Rust5/357、混在31/326、領域6/588・0/117・9/91、
色ヘッダー2/17は維持した。追加推論なし。走査対象が増えるコストは未計測。
未知文書での汎化とモデル誤読は残る。モデル/文字集合と復号は変更していない。
