# P3: 実Page内の二分割境界と元glyph BBoxの診断

## 実装前仕様

P1の全864 Page出力はfresh通常版の6 API経路と一致し、認識直前16,806 cropとOの928 partが
独立PILとbyte一致した。P2では実インク損失も存在した一方、池→油の既知1例は該当字形の
全画素が残っていた。次は既存117成立planの境界自体がlogical glyphを切るかをNNなしで調べる。

- 全619 plan記録を保持し、成立117と不成立502を区別する。採用14/棄却103だけを選別しない。
- 各成立planのRGB/寸法をP1の実primary cropへ結合する。同一RGBが複数座標にあれば全aliasを残す。
  原点は実cropのy0で、回転列の境界を元画像y座標へ戻す。
- 各routeの内側境界だけを一度ずつ調べる。crop外周の切断はP2に残し、内側境界の切断に混ぜない。
- 元glyph BBoxが境界を厳密に跨ぐ場合を記録する。完全包含/部分交差/枠外のすべてを区別し、
  部分字形を除外して「安全」と報告しない。枠外の理論上の交差を実crop内の切断と同数にはしない。
- 注釈のない図形を安全な字形とみなさず、未注釈を別に保持する。
- 境界接触、外周、重複境界、部分/枠外、隙間/不正なrouteをRed/Greenで先行する。
  小さな全矩形を独立した画素座標集合の包含/交差oracleと比較する。
- 全出力と元GT/PNG/BBoxを保持する。追加NN/load/forwardは0で、製品の分割や採用条件を変えない。
  CLI全経路の採点gateは依然未完了であり、この診断だけでOの採用や精度向上を宣言しない。

既知入力による原因調査であり、今後の境界方針の検証には別仕様・新しい未測定対照を必要とする。
