# 孤立した下側の小画線に本文の文脈を保持する

## 実装前の仕様

36px和文のbands cropで幅25pxの読点だけが独立chunkとなった。
全幅で読めない長行の追加認識が、このchunkの `...` / `1.` と低confidenceにより棄却される。
元画像には欠落がなく、0/1/2/4/8pxの上下余白では解消しない。
前/後のchunkと結合する診断では、30/100両モデル・2字体の全8条件で全文120字が完全一致する。

文字内容を選択へ渡さず、`split_line_for_input`の最後で次を全て満たすchunkを前へ結合する。
既存の行頭小記号や上下2画線の復元処理は緩めない。

- 行高16px以上、前chunkと座標が連続し、対象幅は行高以下。
- 対象直前は実単語空白ではなく、実gapが行高の1/4以下。
- 前chunkは幅2行高以上で、その前景高さも行高の1/2以上ある。
- 対象の220前景は3画素以上の単一8近傍連結成分。幅/高さは行高の半分以下で、全て下半分にある。
- 結合幅が実モデル入力比率に収まり、結合内の内部gap数が20未満で、既存の前景列群上限20を守る。

前chunkの終点を対象終点へ延ばし、対象だけを取り除く。前chunkの空白metadata、
後続chunkの空白metadata、RGB/行bbox/順番は保持する。単独記号、中央/上側画線、
非連結点、空/1pxノイズ、実単語空白、入力容量不足では変更しない。

先に未実装Red、幾何の境界/負例/拡大・平行移動/被覆PBTと実モデルのRedを確認する。
同じ文字をdictで置換せず、認識に渡す文脈を変える。

## 採用ゲート

新24画像は診断結果の閲覧前に固定済み。元79＋新24の全103画像、CLI DEIM/bandsと
PageRecognizer30/100の全4経路×none/width/strictで、画像別文字距離1236件の非悪化を要求。
単語指標も全件報告する。通常/ONNXの回帰一式、従来chunkの既知正読・pixel保存を確認する。
合成/既知変形の開発回帰であり、未知実資料の汎化や速度向上は主張しない。

## 結果

元103画像×4経路×3正規化の全1236文字距離は非悪化。CLI 10本文組が改善し、
他402本文組はbyte同一。36px和文2例はbandsで117→0、120→0/各120字。
新たに固定した40px太字和文も135→4/135字へ改善した。
PageRecognizer30/100は各103本文と全bbox/confidenceが同一。
CLI DEIM設定で改善した3例は有効DEIM cropがなく、帯fallbackによる認識だった。

新しい太字対照のCLI両設定では、空白区切りの単語誤りが各1→2となる。
none/widthの計4指標の退行を記録し、先行の画像別文字距離ゲートと分離する。
通常533件＋追加境界2件、ONNX対象459件、fmt/diff/対象Clippy成功。
全件証拠・採点・SHAと再現手順は `docs/benchmarks/isolated-trailing-mark/README.md`。
未検出時に空となるPageRecognizerと、CLIの帯fallbackの差が次の改善対象。
