# 同一クラスの近似同一DEIM領域を一度だけ認識する

## 先行仕様

長行の固定対照 uri_gothic36 で、DEIMは同じ1行に
[224,0,2494,39]、[152,0,2479,40]、[168,0,2488,41] の3領域を返す。
同一クラスなので現行の異クラス専用IoU選択をすり抜け、ほぼ同じ本文を3回認識する。
長行の中央分割候補では、このうち弱い1領域だけが小さく退行した。
検出スコア最大の領域は[224,0,2494,39]。元/移動した切断位置の認識はcolon一字の差で、strictでは同一になる。
初回の診断でPARSeqの平均認識confidenceをDEIM検出スコアと取り違えたため、両方を別々に記録して再確認する。

生DEIM API/検出閾値/モデルは変えず、認識前の選択を次のように一般化する。
有効なline_クラス同士の領域が既存の90%以上IoU条件を満たす場合は、
クラスが同じか違うかによらず最高信頼度の一つだけを認識する。
同点は元の入力順、抑制済み候補での連鎖抑制はしない。
異なる物理行、IoU未満、異常座標/非有限confidence、非lineクラスの扱いは維持する。
勝者の全metadataと元の順序を維持し、字句の一致や文書種別で選ばない。
同一クラスを常に保持する旧内部挙動は、今回の重複認識の証拠に基づいて変更する。

単体/合成/PBTと実DEIMの1行への選択を先にRed化する。
長行分割の製品変更を外した独立binaryで、固定26長短行+既存20画像の
DEIM/bands・none/width/strictの全276画像別指標の非悪化を要求する。
その後、長行の境界変更はこの独立binaryを比較元として再評価する。
一つの改良の退行を他の改良の利益で相殺して採用しない。

## 結果

単体/PBTの2 Red→3 Green。実DEIMは3 queryを維持し、認識cropだけ1へ減った。
DEIMの真の検出スコアは0.5318/0.3866/0.3582で、最初の[224,0,2494,39]を保持する。
勝者のbbox/score/文字数metadataを生検出と照合した。
認識confidenceを検出scoreと取り違えた初回テストの失敗と訂正も記録した。

長行処理を元の実装に戻した独立binaryで、全46画像×2設定の276文字指標が非悪化。
新規DEIMの4組が生116→18、244→105、242→17、129→7へ改善。他88本文は同一。
既存20画像の40本文はすべて同一。新26画像の前版52プロセスと候補全46画像の
92プロセスを実行し、既存比較元40本文は同じbinary/image SHAを確認して再利用した。
通常507件、実DEIMを含む4件、fmt/diff/対象Clippyが成功（既存17警告）。
全出力・採点・コマンド/SHAは `benchmarks/deim-same-class/`。

長行の境界修正は別途、この独立版を比較元にして再評価する。
