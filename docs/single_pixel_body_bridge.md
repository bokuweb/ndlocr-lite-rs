# 1画素で接触した本文字形と閉じ括弧

## 実装・追加認識前仕様

比較元は `db252066713fa5cf075b3ac23512b0b869420576`。旧2,871入力の実API記録には、
rawが正読なのに後処理で失われる571組が残る。既知の `情報)` は全3モデルのrawが正読でも
`情報` になる。本文bbox `[8,8,48,28]` の2文字が `(27,15)` の1画素で繋がり、
8近傍collectorが1成分と数えていた。これは既知の開発回帰で、未知holdoutではない。

まずtest-onlyの診断として次の条件を固定する。F/Gの余白再認識は復活させない。

- 元RGB、RGB和660の閾値、8近傍・面積のcollectorを変えない。
  製品接続時も単行closer fallbackだけに適用し、raw/候補API・fragment・confidence・NN forwardは変えない。
- 対象fragmentは3 Unicode scalar、端に既存5種類 `) ） 」 』 】` のcloserが1個だけ。
  本文2文字はともにUnicode表示幅2、空白とcloserを含まない。
- 既存の面積フィルタ後に成分が2個で、本文とcloserの左右順が文字順と一致すること。
  本文高をHとし、closerとの水平gapは0/1pxだけ。closer高はH/2〜3H/2、
  幅はceil(H/4)〜floor(H/2)、bboxを完全に塗り潰した矩形は支持しない。
- 本文bbox内の全前景画素数が元成分の面積と一致すること。他の独立した小画線を混ぜない。
  内部で前景が1画素だけの列を、水平中心に最も近い順・同距離なら左から1列だけ選ぶ。
  その画素が左右それぞれの前景と8近傍で接続していること。
- その1画素だけを**支持用マスク**から除く。左右はそれぞれ単一の8近傍成分でなければならない。
  各字形の高さはceil(3H/4)以上、幅はceil(3H/4)〜floor(3H/2)、面積は既存閾値以上。
  追加の未訪問画素があれば不支持。分離したbboxと元closerを既存 `supports_collected` でも確認する。
- 元RGBの画素を削ったり、NNを再実行したりしない。支持された場合もfragmentそのものだけを保持する。
  ASCII空白の挿入/削除、本文の文字置換、closer種類の推測は行わない。不明なら基準動作を維持する。

最初に単一接続を分ける純粋関数のRed→Greenを行い、次に文字列/closer支持のRed→Greenへ進む。
2本の接続、分離済み/片側未接続、余分な小成分、塗り潰しmark、gap2px、幅/高さの閉じた境界、
不正RGB/寸法、元RGB不変、方向を例示する。PBT各64例で白紙追加・平行移動・閾値未満の灰度を検査する。
1画素の接触を対象とするため、任意のraster拡大で支持が不変とは仮定しない。

## 精度検証

- 旧2,871画像×3モデルの保存rawを再使用し、実際の基準API本文と新しいRust単行方針を比較する。
  元NN・画像・truth・sourceのSHAを照合し、25,839文字/単語指標をnone/width/strictで全件採点する。
- F/Gの4,598入力も基準版/診断版の同じRust方針で再生する。異なる資料群を独立標本として合算しない。
- 新たな本文は `性格` / `枝葉`、同じCoreText3字体、18/30px、palt=0/1。
  5closer・先頭/末尾・ASCII空白0/1/2個・PNG/JPEG75・上下紙0/8pxの2,880入力を固定する。
  加えてcloserなし、細縦線1px、幅ceil(H/4)の縦線、4×4点の4形状を、本文の先頭/末尾に
  gap0/1pxで置く負例を768入力固定する。形状を含まない本文だけをtruthとし、重なり画素数を記録する。
  合計3,648入力。形状の高さ/位置は本文の実ink bboxを基準とし、本文RGBは保持する。
- font file/glyph/空白advance・全元RGBを認識前に検査し、全ROIを1forwardで3モデルに認識させる。
  source/binary/model/charset/input/コマンド/終了を保存する。新しい結果を見て条件・画像・truthを調整しない。
- いずれかの群で文字/単語指標に退行があれば採用しない。通った場合だけ製品へ接続し、
  全選択入力と負例の公開API/CLI、ページ8経路、通常/ONNX回帰を検査する。

固定fontの合成開発対照であり、未知資料や速度の改善は仮定しない。

## 新規ROIの方向と画素の契約

短い3文字と上下紙8pxでは既存Autoが回転する場合もあるため、その入力を除外しない。
凍結したHorizontal whole-ROI exporterへ渡す前に、Autoの条件 `5h > 4w` の場合だけ
原RGBを90度反時計回りに並べ替える。回転なし/あり両方で、原RGBのAuto前処理と
この有効RGBのHorizontal前処理が3モデル全入力tensorでbit一致することをNN前に検査する。
原寸法/原RGB SHA、有効寸法/有効RGB SHA、回転フラグを別々に保存する。
字形支持と比較方針には原画像を使い、Autoが縦と判断する入力では新しい支持を使わない。
負例の形状は本文ink bboxの外に置き、JPEG保存前の本文の非白画素を保持する。

これは既知の合成開発データであり、未知資料の改善率とは扱わない。

既存fallbackが失敗した後にだけ同じ支持を接続する。純粋テストも単行APIの期待を変更してRedを確認する。

方向固定APIの追加監査では、Autoが回転した128入力を元の向きのHorizontalでも別に認識する。

## 固定した新規対照の結果

3,648画像×3モデルの全10,944 forwardが正常終了した。元Autoのtensorと有効Horizontalのtensorは
全3モデル形状でbit一致し、30モデルの実推論直前RGB全3,648件も有効RGBのSHAと一致した。
32,832文字/単語指標に退行0。変更18本文はすべて空白なし・末尾closerで、ノイズ768入力は全件同一。
生文字/単語距離の完全一致回復は30モデル2・50モデル4・100モデル0の計6。
全半角を揃えるwidthでは各6・8・4の計18完全一致回復。生距離同点の半角closerを生の完全一致に数えない。
Horizontal固定の追加128画像×3モデル・384 forwardも正常終了し、全本文同一、1,152文字/単語指標に退行0。

既存/追加Auto/追加Horizontalの保存raw計33,735組は、接続後の実製品処理と凍結した診断出力が全件一致した。
これは新たな33,735 NN forwardではなく、同じ固定rawを用いるRust方針の比較である。
純粋画像と公開Sessionの `情報)` → `情報` の失敗を先に記録し、最後のfallback追加後にGreenとなった。
3モデルの単行Session/Pool/batch/standalone・候補/raw/fragment、元RGBとconfidence bit不変、
エラー後再使用・Cascade開始3/2/1も成功した。復元候補は常に3字で25/45字の再認識境界は跨がない。
