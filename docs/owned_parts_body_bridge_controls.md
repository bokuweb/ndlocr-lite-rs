# 接触と分離部品案の追加native対照

## 生成・追加認識前仕様

`docs/owned_parts_body_bridge.md` の固定した支持条件を変えない。
保存115,023組では本文変更21組、生完全一致14・width完全一致19回復で、全正規化の文字/単語退行0。
この既知例だけで採用せず、次の新しい順序のnative描画を固定する。

- 本文は `情事` / `事情`。同じ2字の順を変えて左右の部品所属を検査する適用対照であり、
  未知字形/font/実資料のholdoutとは扱わない。語句の置換や辞書を実装しない。
- 同じ3font file、20/32px、palt=0/1、本文内ASCII空白0/1/2、5closerの先頭/末尾、
  closerと本文間のASCII空白0/1/2、上下紙0/8、PNG/JPEG75で8,640画像。
- 本文内空白も含む同じnative本文に、本文だけ/細縦線1px/幅ceil(ink高/4)縦線/4×4点を、
  先頭/末尾・gap0/1・PNG/JPEG75で加える2,304非文字負例。負例には上下紙追加を行わない。
  合計10,944入力、native renderer 2,232記録。
- この段階はnative描画のみとし、人工的な本文間の橋追加・肥大・advanceの圧縮は行わない。
  接触の有無はfont/サイズ/paltのnative画素に従い、人工的な2接続等は先行の純粋テストで検査する。
  追加の人工変形を行うなら、この評価とは別の認識前仕様へ固定する。
- 元の全非白画素の保持と非文字shapeの重なり0を検査する。font fileのSHA、実glyphと空白advance、
  全ファイルSHA/組合せ/真値/PNG-JPEGの元RGBを固定し、少なくとも72例を目視する。
- 追加NN前に、真値を仮rawとして与えた支持だけも全画像で記録する。
  幾何的な到達性の診断であり、NNの認識結果/精度/改善数へ合算しない。
  支持0や不都合な行を除外せず、全入力を保持する。判定条件を結果へ合わせ直さない。
- Auto回転も除外せず、全入力について元Auto/有効Horizontalのtensorを3モデル形状でbit照合してから
  全ROIを1forwardで認識する。回転した元画像はHorizontal指定でも別途測定し、独立標本へ数えない。
- 固定した原画像の保存rawを、実fc5製品処理/test-only案で比較する。
  旧新全群のnone/width/strict文字/単語のいずれかが悪化すれば、本案の接続を止めて反例を保存する。
  新NNの実際の適用がない場合も、そのまま採用しない。
- 全件が非悪化かつ追加対照にも適用した場合だけ、別の公開接続仕様と純粋/実SessionのRedから進む。
  Source/executable/model/inputを先に固定し、全選択・境界・方向の公開API/CLI、raw/候補/fragment/mean、
  全スイートとpage fragment経路の不変性、独立復元を前段と同様に確認する。

幾何診断の増分適用が0なら、追加NNへ進まず全入力と診断結果を保存する。
新しい適用対照が必要な場合は、追加結果に合わせた条件変更をせず別仕様へ固定する。
