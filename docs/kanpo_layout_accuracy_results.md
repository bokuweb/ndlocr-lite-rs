# 官報OCRの段分離・重複改善結果（2026-10-23）

既定の検出閾値0.25を保った修正版は、最終の独立確認2段1,069文字で
**1誤り / CER 0.094%**。同じ画像・正解のTesseract.js 6.0.1は
**36誤り / 3.368%**だった。各3回の生テキストは両者とも一致した。
この官報横書き資料の検証範囲で精度目標を達成した。一般文書全体での優位を保証する結果ではない。

## 比較条件

Apple M6 / 32 GiB / macOS arm64。release + onnx、同一PNG・固定モデル、逐次・新processで各3反復。
NDLOCRはDEIM + PARSeq30/50/100、検出0.25、行confidence0.3、quality boost無効、
structure rules無効、辞書・rule packなし。Tesseract.js **6.0.1**、固定tessdata_fast jpn、
LSTM / OEM1 / PSM3 / DPI300。NFKC+空白除去は採点時のみで、生出力を保存した。
公式`tools/eval_ocr_metrics.py`のLevenshteinを使い、全生出力のSHAを再照合した。

基準はcommit `0ba1c0007c12c91f2527d40a9033ca7815d18795` の元release binary。
lawrenceanumのソース・未コミット変更・既定Tesseract設定は変更していない。

開発用と独立確認を混ぜた平均は独立性能として主張しない。
GTは画像を拡大し主担当agentが直接転記したもので、OCR出力を正解にしていない。
一人の転記であり、人間二名による独立校正済みcorpusではない。
GT・PNG・ROIを認識前にhashで固定し、結果に合わせて書き換えていない。

## 直した原因

1. 従来のfallbackは全幅のY投影を使い、4段のずれた本文を巨大な1領域へ結合していた。
   全高の空白と、各区画の繰返し横書き行が支持する段を分け、各段で行を抽出する。
2. 読み順は段の左→右、段内の上→下とする。数字1文字の折返し行が縦長bboxでも
   横書き段内の順序を破棄しない。初版の失敗をテストと生出力で保持した。
3. 検出0.9はfallbackの指定ではない。追加2段ではDEIMが**14行だけ残り**、
   fallbackが発動せず1,306誤り / CER87.592%となった。閾値0.9の一律採用は棄却した。
4. 既定0.25で、画素が確認する複数の横書き段、または均一な複数行に繰り返す
   完全行/包含断片の競合があるときに、認識前に横書き帯を選ぶ。
   見出しの競合だけで巨大な本文帯へ切り替えない保護を追加した。
   単行、曖昧な1行だけの競合、無効候補、縦列を切替根拠にしない。

文書名、会社名、人名、正解語、画像hashでコア処理を分岐していない。
個別語の置換・辞書・GT修正による改善ではない。既知cropの葛→蔦は残る。

## 欠落・重複・順序の確認

最終独立確認は**置換1 / 挿入0 / 削除0**、80物理行を80行として認識。
番号列12件の順序、先頭末尾24文字、余分な同一正解行の重複0を確認した。
もう一方の追加2段は97/97行、置換1・挿入/削除0、番号列・先頭末尾も一致した。

追加全文は179/179行・番号列・先頭末尾一致。ただし文字誤りは残り、
最短編集整列で削除7・挿入1・置換3、合計11。全文無誤りとは主張しない。
編集整列の削除数や、GTのない画像の出力文字数を、画像上のrecallそのものとは扱わない。
既知の番号付きcropのGT改行は論理的な折返しで、実画像12行とGT10行の差は欠落ではない。

GTのない従来3全ページは、fallbackの認識前領域11/9/17から185/179/187へ変わった。
これは巨大領域の解消の確認値であり、これだけで精度・被覆率の改善とは判定していない。
`--trace-json` はDEIM候補・構造選択理由・候補除外・認識crop・認識結果・confidence採否・
context整理・最終順序・本文を別JSONに保存する。診断の有無で8入力のTXT/stdoutが一致した。
DEIMの候補数は指定閾値を通過したline_*候補数で、モデル内部の全logitではない。

モデルsnapshot・読込・出力保存を含む新process境界。最大RSSは`/usr/bin/time -l`であり、
子processすべての同時メモリを合算した値ではない。マシンには他作業のCPU負荷があり、
各試行の時間は揺れている。速度の優位は未達で、今回の改善は精度・構造処理の改善である。
