# 行頭の孤立した小記号の文脈を保持する

2026-10-18。JMAお知らせの既知開発入力では、丸点だけを幅29pxのchunkにし、
残りの本文を別chunkとしていた。固定30文字PARSeqで最初の2chunkをまとめると
1行目は `..` → `•`、2行目は `.. ` → `・`。後者は依然誤りである。
正解文字への置換や辞書は使わず、元画素のまま認識文脈を保持する。

対象は横書き行の最初の2chunkだけ。先頭区間は高さの1.5倍以内、全インクが
縦横とも行高の半分以内に収まる1つの8連結成分で、3画素以上とする。
次のchunkは確認された実単語空白で区切られ、通常本文を支持するインク高が
行高の3/4以上必要。区間は隣接し、結合後がモデルの実入力比率と既存20字形列群
未満の上限に収まるときだけ1区間にする。これ以外のchunk/単語境界は維持する。

先に実画像2行と合成例のRedを固定する。普通の大きな先頭文字、複数成分、
本文高が足りない相手、実単語空白なし、非隣接、モデル容量超過は変更しない。
PBTで拡大・平行移動・入力幅境界と元RGBの無欠落/無重複を確認する。

公開前にomoの既知19入力で変更があるページは両方式を再推論し、全入力それぞれで
生/正規化文字距離の非悪化を要求する。同一資料の本文と切り抜きを独立資料とは
数えない。未知資料・学習重複・release性能の保証はこの開発回帰から主張しない。
