# 横だけの縮尺に対する、句読点空白候補Dの追加対照

## 測定結果: Dを棄却

初回のexporterは30モデルの14 ROIを2chunkへ分割したため、単一区間の条件を満たさず採点に使わなかった。
全出力とコマンドを保存し、`whole_roi_candidate_export.md` の明示opt-inをRed→Greenで追加した。
同じRGB/真値の全2,304 ROIを3モデルで再認識し、各1chunkと全元画素を確認した。
初回に単一区間だった計6,898 ROIは、候補・確率・停止理由を含むJSON値が一致した。

全2,294件・20,646文字/単語比較で、none/widthに18文字・18単語指標の退行があった。
9本文組（全て100モデル、横65%）は `案内方法、 連絡先` の正読から空白欠落へ0→1となった。
生距離改善120組/完全一致回復76組があってもDは棄却する。strictは空白を除くので退行を隠す。

## 追加認識前仕様

独立点を含む1,718入力の診断Dは15,462文字/単語指標で退行0だった。
製品接続の全経路比較は実行中。まだ採用済みとは扱わない。
H基準の白列支持は横だけの縮尺に不変ではないため、新しい文と縦横比で検査する。
Dの条件と既存1,718件の画像・真値・候補は変更しない。

- 新しい文は `案内方法、連絡先` / `準備作業。確認箇所`、句読点後のASCII空白0/1/2個。
  既存3字体（丸/角ゴシック/明朝）の24/40px。必要文字のmaskと空白の送り幅を検査する。
- 描画bbox周囲2pxを含む元画像を、Pillow BILINEARで幅だけ65/80/100/120%にする。
  幅は `max(1, floor(original_width * percent / 100))`、高さは変えない。
  その後に上下各0/6pxの白紙を追加する。真値は変更しない。
- PNG/JPEG75を保存し、decode後のRGBを固定する。
  2文×3空白形式×3字体×2サイズ×4横縮尺×2紙文脈×2形式=576入力。
  左右各2px/上下各0・1・2pxの3候補を原画素保持で追加し、元画像と計2,304区間にする。
- font/Pillow/source/model/binary/全入力SHAを認識前に固定し、全候補各1chunkを要求する。
  既存Dと同じ凍結Rust geometry/boundary probe、同じ候補/信頼度条件、公式scorerを使う。
- 固定1,718件をSHAで再利用し、合計2,294入力×3モデル×3正規化の20,646文字/単語指標を比較する。
  追加対照で1件でも退行があればDの製品採用を棄却する。
  結果を見てDの条件や真値を変更しない。改善の合計で相殺しない。

未知実資料や任意の縦横比への汎化は仮定しない。
