# 文字成分の幅を加える空白支持E

## 診断結果

固定3,446件・31,014文字/単語比較で退行0、生距離改善82本文組、完全一致回復56組。
連結字形では幅anchorがなくなり、既知のページ対象区間も見送る。
Fも新規認識前に別仕様で固定し、同じ未認識1,152件を共通対照として検査した。
Eはtest-onlyの比較案として保持し、製品接続はFで行う。

## 実装・追加認識前仕様

Dは横縮尺の追加対照で棄却した。9本文組の正しい空白が消え、none/widthで
18文字・18単語指標の退行となった。いずれも100モデル、横65%の `案内方法、 連絡先`。
画像・真値・Dの条件・全結果は変更しない。ページ1画像の回復もDの採用根拠にはしない。

EはDの候補/本文/信頼度条件をそのまま使い、画像支持だけを更に狭める別案。
まずtest-onlyの診断で検査し、製品接続は後の段階とする。

- 元の8近傍collectorとRGB和660閾値、area/Hの算出・成分除外は変更しない。
  内部最大白列G、成分最大高HもDと同じとする。
- 高さが `3H/4` 以上、幅がH以下の成分を幅のanchorとする。
  短い句読点・横に複数文字が繋がった広い成分を、単文字幅の根拠にはしない。
  anchorが2つ以上の場合だけ、2番目に大きいbbox幅をWとする。
- 支持はDの `0 < 4G <= 3H` に加えて `4G <= 3W` を満たす場合だけ。
  Eの採用集合は同じ入力のDの採用集合を広げない。
  不正RGB・全白はNone、anchor不足・白列なしは非支持。
- 例示で幅の狭い2成分/幅12と高さ12の2成分、anchor不足、縦/横の広い塊、閾値を検査する。
  PBTでは高さを固定し、anchor条件を保つ整数の横縮尺と白紙/灰度を変えて、
  W/Gの比例と支持の不変性を検査する。任意のraster縮小で連結成分が不変とは仮定しない。
- 既存2,294入力と全生候補はSHA検証で再利用する。
  新しい文は `確認事項、担当課` / `開始時刻。集合先`、句読点後ASCII空白0/1/2個。
  既存3字体、22/36px、横60/75/90/110%、Pillow BILINEAR（幅floor、高さ固定）。
  周囲2px、紙は上下0/8px、上下8pxと上端4×4点、上下8pxと本文中央高の4×4点の4文脈。
  点のxは変形後の元字形の最大内部白列群の中央（同幅は左、なければwidth/2）。
  全黒点を画像内へ収め、本文/真値は変更しない。
  中央点が字形へ接続/重なる場合は元の画線との重なり画素数を記録し、不変性を仮定しない。
  PNG/JPEG75保存後のRGBを固定し、必要文字mask・空白送り幅・font/Pillow SHAを検査する。
- 2文×3空白形式×3字体×2サイズ×4横縮尺×4文脈×2形式=1,152追加入力。
  左右各2px/上下各0・1・2pxの3候補を元RGB保持で作る。
  `--whole-roi` で3モデルとも全4,608 ROIを各1forwardで認識し、全画素/単一区間を検査する。
- 合計3,446入力×3モデル×3正規化の31,014文字/単語指標を公式scorerで比較する。
  追加対照を見てEの条件・真値を変更しない。1件でも退行があればEを棄却する。
  通った場合もcallback・方向/容量・全公開API・実CLI/ページの比較を終えるまで製品採用としない。

画像の幅だけで文字数や意味を推測せず、返すのは一致した実モデル候補そのもの。
未知実資料、任意の汚損/縦横比、速度の改善は仮定しない。
