# 空白支持Fの製品接続

## 実装前仕様

E/Fを共通の未認識1,152入力へ適用した結果、各案31,014文字/単語指標の退行0。
Eは82本文組改善/56完全一致回復、Fは114改善/70完全一致回復となった。
Fを接続する。Dは棄却し、現在の通常経路は9fc4528の基準動作へ戻している。

- Dで検査した同一Sessionのcallback・方向/容量・3余白候補・失敗時の元結果保持を維持する。
  画像支持だけをFの `0 < 4G <= 3H && 4GN <= 3S` に置き換える。
  Nは元デコードからASCII空白1個を除いたUnicode scalar数。
  既存のraw/候補API、供給モデル、threshold25/45のcascade振分けは変更しない。
  対象は最大13文字であり、削るのは1個のASCII空白だけなので25/45を跨がない。
- 連結した語ブロックを模すcallback正例と、Dだけが支持する狭い字形/実空白の負例をRed先行で検査する。
  横65%の実空白反例は実モデルでDの失敗を確認済み。F接続後も元本文/信頼度を保持すること。
- 全3,446入力・3モデルについて、実モデルで保存した元/3候補をRustの実選択関数へ渡す。
  callbackの全RGB・寸法・順序・回数を検査し、通常単行/断片の両sanitizerを通す。
  返した値と公式none/width/strictのbaselineとの差を全件比較する。
  これは固定実出力によるRust内replayであり、新しい全件NN再実行とは区別する。
  rawデコーダ/forward/NN入力に差分がないことと、元AutoがHorizontalになることも確認する。
- replayで影響する全入力IDに、既知の実空白反例・元の負例pin・新ノイズ/横縮尺の負例を加える。
  この明示した対照集合を基準版/新F版の3モデル・全7処理済み単行経路とraw経路で新規に認識する。
  本文とf32 confidenceをreplayとも比較し、原画像/候補API・エラー後再利用・混在bucketは実モデルテストで検査する。
- 対照外の未選択入力は、元のNNと既存sanitizerへ戻る同じ経路であることを検査する。
  Dの全1,358入力×8経路の実測も保存するが、Fの新規NN全件測定とは称さない。
- 287画像のページ8経路（30/50/100の評価/既定API、DEIM/帯の実CLI）はF版で全件新規実行する。
  変更前はsource/入力/出力SHAを検証した9fcと同一productionの保存済み参照値を再利用する。
  本文の公式文字/単語指標、行数・bbox・confidenceを比較する。
- いずれかで退行があれば採用しない。NN値の差や経路差があれば該当入力を新規認識して調べる。
  source/binary/model/charset/全入力を実行前に凍結し、全プロセスの終了を確認する。

固定フォント対照と既知ページの開発回帰であり、未知実資料や速度の改善は仮定しない。

## 接続結果

- 画像支持の狭い字形負例をRed→Green。既存のD正例はFが棄却するため、実モデル30の
  pinを既知ページ由来の `測定場所、 時刻、` → `測定場所、時刻、` に変更した。
  旧pinも累積3,446入力に残し、truthは変更していない。
- 保存した実NN結果の10,338組を、Rust製品選択・両sanitizerで再生した。
  全callbackのRGB/寸法/順序/回数と選択が一致し、62,028文字/単語指標に退行0。
  114組の文字距離改善、うち70組が完全一致へ回復する。
- 全100選択入力IDと既知反例/層別負例の和集合158入力を、基準9fc/Fの全8単行経路で新規認識した。
  全7,584本文とf32 confidenceが製品replayと一致し、11,376文字/単語指標に退行0。
  供給3モデルのbatchがstaticであることも実Session metadataで確認した。
- 単行CLIは前後計14プロセス。3正例を完全一致へ回復し、4負例を保持した。
  公開実モデル5テストで、同Sessionの再使用、raw/候補API不変、エラー後再利用と混在bucketを検査した。
- Fのページ287画像×8経路は全件新規実行し、比較元9fcのsource/入力/本文SHAを検証した参照と比較した。
  全6,888文字/単語指標に退行0。30の評価/既定設定の丸字体24px半縮小1画像で
  生/width文字距離1→0、単語距離2→0。他2,294本文組はbyte同一だった。
  API全1,722組の行数・3,460行のbboxは不変。confidenceの変更もこの2組だけで、CLI574本文は全byte同一。
- 通常639件・ONNX実モデル556件・example23件、fmt/diff/Clippy成功、新規警告0。
  `docs/benchmarks/punctuation-space-context/` に採用Fと棄却C/Dを区別して保存する。

丸字体36px側の誤空白と、別の挿入誤りは残る。追加の比例組版対照は
`docs/punctuation_space_proportional_controls.md` に別仕様として固定し、目的全体を継続する。
