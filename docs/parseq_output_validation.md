# PARSeq平坦出力の検証（Phase 5）

## 問題と仕様

通常のONNX推論が利用する平坦logitデコーダは、非有限値と文字集合の
不一致をエラーにせず、空文字や文字欠落を正常な認識結果として返していた。
候補取得APIと同じ検証を共有し、誤ったモデル・設定の組合せを検出する。

- `timesteps`と`classes`は正、積は`usize`内、バッファは積以上であること。
- EOSを含め、`classes == charset.len() + 1`であること。
- 形状内の全logitは有限値であること。EOSや低信頼度停止の後も検証する。
- 形状外の末尾データは従来どおり無視する。
- 正常入力の本文・空白・反復・停止条件・信頼度と演算順序を変更しない。
- 通常・信頼度付き・候補付きの平坦APIに適用する。Vec行APIは対象外。
- 候補用配列の確保より前に検証する。検証を重複して走査しない。

## 先行テストと検証

非有限値（NaN/正負Inf、EOS後を含む）と文字集合の過不足でRedを確認する。
ゼロ・積のoverflow・短いバッファ・形状外NaN・有限極値を回帰ケースとし、
PBTで形状内の任意位置の非有限値拒否と正常値の有限信頼度を確認する。
既存候補テスト・通常全体・実ONNX回帰を実行する。
既存デコードbenchの文字集合数をEOSと整合させ、同じ入力で変更前後の
デコード時間を測定する。これはOCR全体の速度測定とは区別する。

## Green後の走査の整理

全形状の検証追加で合成デコード時間の増加が観測された。
検証範囲・有限値の条件は保ち、非有限値判定を論理ORの集約へ整理する。
短絡評価を避けることで自動ベクトル化を可能にし、既存の境界/PBTと
実モデル回帰を維持したまま同じbenchで再測定する。
