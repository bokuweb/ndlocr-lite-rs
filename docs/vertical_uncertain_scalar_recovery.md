# 低信頼な一文字と異なる二分割の文字別合意

## 候補N: 実装・新画像・追加NN前の仕様

候補Mは全270入力/model組で退行0だったが、改善は既知の2画像だけで新72画像の改善は0だった。
Mを製品へ接続しない。容量近傍の元rawと二分割の全文が合意しない場合でも、同じ一文字だけが
異なる例があり、その元winnerは低信頼な場合がある。この失敗様式を次の固定案で検査する。
MのデータはNにとって既知の開発回帰とし、新規holdoutとは呼ばない。

### 対象と維持する処理

Mの原RGB/Otsu支持/二分割planを維持する。実output metadataから得たT近傍、原幅/長さ/支持、
異なる主/副境界、元raw末尾Unicode空白の除外、全chunkの非空白/finite平均0.9..1/T未満、
全文の一致/厳密延長/4種alphanumeric/Unicode空白列一致を保つ。
Hは変更せず、H採用時はNを使わない。旧公開splitter、通常SingleLine、raw Session、明示Horizontalも保つ。
文書語彙、GT、書体、ファイル名、既知行の文字列は採否に使わない。

### 一文字の訂正を許す追加条件

- 元rawと全chunkは、既存のgreedy decoderが返した実top-1候補traceを必要とする。
  各emissionのUTF-8範囲/文字/先頭候補/非EOS token id/finite確率0..1がliteral本文と一致することを検査する。
  欠落、重複、不正range、文字不一致、空候補、非有限確率は候補なしとし、文字indexとbyte indexを混同しない。
- 全文合意が元rawの完全prefixを保つ場合はMと同じ延長を候補にできる。
- それ以外では、合意全文の先頭`元raw scalar数`文字と元rawの間で、異なるscalarがちょうど1個の場合だけ扱う。
  この位置の元字と新字は両方alphanumericでなければならない。句読点・空白の置換、複数文字差、
  一致しない長さのprefix比較や部分出力は採用しない。
- その元winner確率はf32の0.9を**厳密に下回る**ことを必要とする。
  同じ全体scalar位置の訂正文字について、主分割と副分割の両方の実winner確率がf32の0.98以上であることを必要とする。
  全chunkの平均値だけをこの文字の確率として使わない。二分割を独立な統計標本とは数えない。
- その他の元raw文字は順序も値も保ち、訂正後のprefixでMと同じ全条件を満たす場合だけ全文を返す。
  confidenceは従来どおり主分割だけのscalar加重f64平均をf32にする。
- traceの取得失敗、不支持、不一致は元rawをそのまま保持する。元認識のErrも保つ。
  NN内部forward数は未計測ならnullとし、画像API数と区別する。

### Red → Greenと新規対照

別sourceコピーのtest-only moduleで先行する。閉じた/開いた確率しきい値、異なるchunk境界をまたぐ
Unicode scalar位置、強い元winner、片方だけ弱い訂正、複数差、句読点/空白差、元prefix完全一致、
失敗/不正traceを小さなRedから検査する。PBTは整数由来の確率と、書き換える位置・chunk分割を組み合わせる。
Mのpure testsと旧幾何replayも残す。既存N未接続の本体へ大きな変更を先に入れない。

新しい3段落を、実metadataの各T-1/T/T+4 scalarへ切り出す。既知3font file×余白0/8で54本文を作る。
Mと同じ48px/52px送りを使い、新段落のGT・描画条件を描画前に固定する。
3背景×2図形×各T+1群の18図形も固定する。全72RGBは旧270RGBとSHA重複させない。
新旧合計342RGB、glyph注釈216本文を幾何検査へ渡す。既知fontによる合成開発対照であり、
未知資料/未知書体/学習未使用の独立holdoutとは主張しない。

字形内部の切断が一つでも残れば追加NN前に候補全体を棄却する。新規GTの長さがT-1の完全文も
必ず含め、余計な延長や訂正をしないことを対照として保存する。既知270入力の全結果は残し、
新72入力を見てしきい値や条件を変更しない。必要な変更は別候補として仕様から始める。

### 評価と本体への接続

同じmodel/charset/source/RGB/寸法/方向の既存raw traceだけ再利用し、再利用を新NN呼び出しと数えない。
全342×3modelの入力別none/width/strict文字・語に退行0、非文字の出力変更0、完全文の誤延長/誤訂正0、
少なくとも1つのN新規RGBの改善を採用条件とする。既知270入力だけの改善で採用しない。

通過した場合だけ借用済みsessionのFragment+Autoへ実モデルnative Red→Greenで接続する。
traceは同じ元認識のgreedy結果に基づけ、通常経路/既存sanitize/Hの結果を保持する。
全342×3modelの単件/batch/専有session、既存H、293ページと既知縦書き7ページ、新対照のAPI/CLI比較と
必要スイートが終わるまでは製品の精度改善と呼ばない。未通過なら全反例とsourceを保存して次の施策へ進む。
