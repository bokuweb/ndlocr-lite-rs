# 句読点後の空白候補Dを同一モデルへ接続する

## 実装前仕様

診断Dは固定1,358入力・3モデルで12,222文字/単語比較に退行0、
生距離改善105本文組・完全一致回復61組だった。Cは棄却済み。
この結果だけで製品採用とせず、次の小さなcallbackと公開APIの検証を先行する。

- 元デコードは内部ASCII空白1個、非空白6〜12文字の和文。
  空白の直前は `、` / `。`、直後は仮名/漢字。同じDのcollector・gap条件を用いる。
- 元confidenceは有限の0〜1。寸法/RGB長/加算/確保を検証する。
  Autoで元入力が回転する場合は対象外。Horizontalなら元寸法を使う。
  左右2px追加後の幅/元高さが、そのモデルの入力幅/高さ以下の場合だけ試す。
  モデルの容量・charset・thread指定を勝手に変えない。
- 同一セッションの後処理前Horizontal推論をcallbackとして渡す。
  元RGBを保持して左右各2px、上下各0/1/2pxの白255だけを追加し、最大3回実行する。
  各候補が元の非空白本文と一致し、confidenceが有限の.98〜1であることを要求する。
  最初の候補は元confidenceより厳密に高い必要がある。選ぶのはこの実候補全体。
  途中のエラー・低信頼・不一致・同点はNoneを返し、呼出元は元結果を保持する。
- raw/文字候補APIを変更しない。通常の単発・Session単行/バッチ・Pool単行/断片で、
  元デコード後・既存画像支持sanitizer前に同じ選択を適用する。
  mutexを二重取得せず、借用中の同じsessionでraw forwardを呼ぶ。
  単発APIも元のthread=1とメタデータ検証を保ち、追加候補ごとにモデルをロードしない。
- callback例示で画素保持・候補順・最大回数・失敗/不一致/信頼度境界と
  容量/回転/不正入力の無呼出しを検査する。小点と余白のPBTは診断Dを引き継ぐ。
- 新しい実モデルテストで少なくとも改善・正しい空白・エラー後再利用とraw不変を検査する。
  同じ固定入力を全単行経路と3モデル、既存287画像を全ページ経路と3モデル/設定で比較し、
  実CLIも確認する。元出力と候補出力を公式none/width/strictで全件比較する。
  退行があれば製品採用せず、原因と全結果を残す。

未知実資料への汎化、速度改善、全空白誤りの解消は仮定しない。
