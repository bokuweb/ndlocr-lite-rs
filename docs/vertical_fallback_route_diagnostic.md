# P4出発点: DEIM欠落時の縦列入力と水平fallback

## 診断の先行仕様

P1の全864ケースと通常API照合が完了した。注釈付き648ケースのうち、111ケースではDEIMが
行を返さず、既存水平band fallbackが各入力を101..146個の領域に分けていた。
対してDEIM経由537ケースは各1領域だった。これは同じ144既知画像・6経路内の回数であり、
独立した111資料の精度を示さない。CLI全体のO採点はまだ継続中である。

- 全864ケースを分類し、原画像ID、model/設定、注釈有無、primary count、using_bandsを保存する。
- band経由の実rawイベントがHorizontalで、Fragment+Auto容量回復を通らないことを全件照合する。
  既存出力を消したり、GTを切り詰めて採点しない。この診断は追加NN/load/forwardを行わない。
- 原trace/manifestのSHAへ結合し、認識文字列とpolicyを変更しない。
- 次候補は、DEIM欠落時に既存の縦列検出を単列の幾何的支持がある場合に接続する方法である。
  現在の縦列検出APIは既知の縦書き向けなので、そのまま自動適用して安全とみなさない。
  横書きportraitページ・単純図形・細い縦線・白紙・既存対照を維持する新しい方向選択仕様と
  Red/Green/PBT、未測定の新規controls、幾何切断検査、全Page/CLI無回帰を別に必要とする。

本文の1文字置換や既存prefix条件の緩和を先に導入せず、既知の方向経路の欠落を検証する。
