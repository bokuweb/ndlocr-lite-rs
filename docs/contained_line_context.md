# 同じ行の包含された認識断片を、信頼できる全体文脈へ戻す

## 実装前仕様

反復保持の初回全件比較は、新しい混合英数字1画像でCLI DEIM / runtime30 eval /
runtime100 evalの各3正規化、計9指標が退行した。DEIMが全文1領域と同じ行の文字/小語を
重複検出している。全文の正しい反復数を保持すると、断片と二重に出力された。
全出力/source/採点を `count-only` として保存し、初回案はまだ採用しない。

元の認識結果の文字は変更せず、すでに認識した同じ物理行の親領域を信頼できる場合のみ
その内側の断片を出力から除く。追加推論、文書種類/語句の置換、隣接する別行の結合は行わない。
DEIMの生結果・入力crop・認識のconfidenceを変更せず、選ばれた結果と元の順序を保持する。

対象は正のbbox、非空text、finiteで0より大きく1以下のPARSeq平均confidenceを持つ結果。
長軸/短軸比が5/4以上の親に、同じ短軸範囲（各辺の差がmax(1,ceil(短軸長/10))以内）で
長軸範囲が親内（同じ許容幅内）にある、親より短い断片を集める。横/縦とも同じ軸の規則を使う。
親の実入力アスペクトは、供給モデルのnative比率以内であることを要求する。

候補断片からconfidence順に長軸が重ならない支持集合を作り、以下を要求する。

- 2つ以上の独立した支持、長軸全体の3/4以上のspan、隣り合う支持間の空白は短軸長以下。
- 親の平均confidenceが支持の長軸幅で重み付けした平均以上。
- 親の非空白文字数の2倍が、支持の非空白文字数×confidenceの合計以上。

条件を満たした親だけを代表にし、内側の候補断片を除く。大きい親から処理し、
除外済みの候補を別の親の根拠にしない。遠い列、別baseline、支持が1つだけ、低品質な全体、
文字をほとんど説明できない全体、native容量超過、無効な値は従来どおり残す。
CLIはロードしたモデルの最小native比率、PageRecognizerは供給primaryの比率を使う。

選択は全認識・既存confidence/空文字フィルタの後に行い、model/sessionの呼出し回数や履歴は変えない。
APIの既保存結果に同じ純粋選択を適用して全件を再現し、実モデルの新規実行で再現結果との一致を検査する。
CLIは構造補正の前の結果を保存していないため、新規実行して比較する。
単行3モデルはこのページ選択を使わないので、同じ認識実装のSHAを照合した予測を保持する。

先に方向・score/量/span/gap/native境界、順序/拡大/移動PBTと、実画像の重複解消をRed化する。
最終採用は全287×6×3と単行263×3×3の7533画像別文字距離の非悪化、単語指標の全件記録を要求する。

## 検証時の型

公開APIのconfidenceはf32である。保存JSONのdecimalをf64で再parse/serializeすると
最終桁だけ変わる場合があるため、新規推論との一致はbbox/textの完全一致とf32の同じbitで比較する。
元JSONは不採用案のarchiveへそのまま保存し、閾値選択も同じf32へ戻して実行する。
全287×4設定の再生後、変更された全ページと29画像おきの安定対照、計44ページを実モデルで再実行する。
