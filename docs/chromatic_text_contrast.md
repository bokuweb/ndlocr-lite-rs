# 同じ明度の色文字と部分ハイライト

混在書式の未調整文書では、赤文字と橙背景の紫文字を同一パネルとして扱い、
背景外の白紙を黒くし、明度が近い紫文字を白くした。公開f7cda79では行の安全分割が
できずページ全体でエラーになる。本文置換やモデル変更では解決しない画像処理の問題である。

仕様: 背景推定には横長の連続色領域の支持を使い、孤立した色文字を背景の標本にしない。
RGBを保持して背景との差を各成分で比較し、平均明度が同じ異色の字形を保持する。
行の背景外の色文字・白紙は変更しない。既存のgradient・白黒文字・隣接色パネル・
長短行は維持する。原寸文書と合成画像のRed、境界/PBT、実ONNXを先に固定する。

採否は既存全文/領域コーパスの誤り数で確認し、悪化する候補は棄却する。


Red: 合成2例・拡大/位置ずれPBT・原寸16行検出が公開f7cda79で失敗した。
全ページの最初の完全一致RedはEngineFailureで、RGB平均に基づく背景標本と
異色の文字の同明度が原因だった。実装は列ごとのRGB中央値と背景色に一致する
行内範囲を使い、モデル・文字列置換・分割選択を変更しない。

Green: 合成/PBTと16行検出・全行安全分割に成功。固定PARSeqでは背景外の赤文字と
背景内の紫文字の両方を同一行で認識する。omo全ページは16行・16/1032編集誤りで、
空白・引用符・括弧などのモデル誤読が残る。正解は初回推論前のまま固定し、
調整済み開発データとして扱う。既存全文/領域コーパスの誤り数はすべて維持した。
追加モデル推論なし。今回の速度は未計測。詳細はomoの
`docs/ocr_formatted_evaluation.md` と `fixtures/expected/ocr_formatted_accuracy/` を参照。
