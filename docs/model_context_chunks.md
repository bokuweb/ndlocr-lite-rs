# 入力寸法に収まる短い行の文脈保持

## 仕様

既存の `split_line` は保守的な幅/高さ比8を維持する。新しい
`split_line_for_input` はロード済みONNXの入力幅・高さを受け取り、行の比率が
入力比率以下かつインク列群が20以下なら行全体を1区間で返す。
それ以外は既存の分割へ委譲する。長い行の分割上限を一律に広げない。
入力寸法0・積のoverflow・不正RGBはエラーとし、整数の交差積で比率を比較する。
`ParseqSession::input_dimensions` はファイル再読込なしで実際の入力寸法を返す。

## 回帰

300dpiの `（電子入札の対象）` は検出後383x47、モデルは256x24。
比率8をわずかに超えるため従来は193/190pxへ分割され、`木入子電)[の対象)`
となった。行全体なら `(電子入札の対象)` で、全角括弧の2誤りだけとなる。
実fixture・境界値・モデル寸法変更・字形数上限・長い行の互換性を検証する。
omo側では白紙検証・本文予算確認後にだけ入力寸法を取得し、セッションを共用する。
既存コーパスの個別上限と全文CERを悪化させないことを採用条件とする。
