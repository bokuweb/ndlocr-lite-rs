# 太字・明朝体の長い縦列

## 先行仕様

Arial Unicodeだけで確認していた長い縦列の内部画線判定を、太字ゴシックと明朝体で検証する。
48px・52px送り、中央に二または三を置いた31文字の4画像・原文・描画矩形を初回推論前に固定する。
検出なしと列検出・切り出し後の双方で、字形内部にチャンク境界を置かず、全文124文字が一致することを要求する。
原文と描画矩形は採点専用とし、分割・推論の判断へ渡さない。
既存の細線だけの列・密な画線連鎖の制限、旧6列、短列、横書きの回帰を維持する。
固定文字列の置換、書体名や原文に依存する分岐は追加しない。

合成開発資料であり、未知実資料や低解像度への汎化は証明しない。

## Redで確認した原因と修正方針

`32e5c18` は太字の7px画線を列幅68pxの1/10以下という条件で除外する。
明朝の6px画線も、検出後の列幅では同条件から外れる。
二の両画線を含む幅36pxは、検出後の列幅に対する2/3の制限も超える。
全画像経路の太字は三1/31・二2/31編集で失敗した。

画線厚みは自身の長さの1/4以下とし、十分な画線長の条件を併用する。
結合全幅の上限は既存の支持字形幅中央値（かつ列幅以下）を使い、列幅2/3の二重制限は除く。
支持字形が6個未満の列と、上限を超す細線連鎖には結合しない。

## 対象の検証結果

幾何テストと24ケースPBTはいずれもRedを確認後、修正でGreen。
固定モデルの4列は全画像で3→0/124、検出後cropで5→0/124編集。
旧6列194文字は両経路で全文一致し、既存の短い手書き縦列4/83編集も維持した。
omoの旧公開依存でも追加4列は6/124編集で失敗した。libraryのcrop経路とは入力処理が異なるため、スコアを区別する。
追加推論は行わないが、OCR全体の速度/メモリ改善は測定していない。
全回帰・公開依存を経由した検証とCIは同じPRの本文で追跡する。
