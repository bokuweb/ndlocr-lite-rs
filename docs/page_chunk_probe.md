# 100文字モデルの全幅入力と安全な水平区間の比較

## 事前固定する診断

URLの途中のunderscoreやhyphenはraw100モデルからも欠落する。
現行CLIの通常cascadeとは別に、全行を固定100文字モデルで認識する診断を行う。
`--enable-cascade false --split-long-lines false` のCLIと同じ検出・crop・断片sanitizer・
信頼度0.3・読み順・構造処理を使い、全幅の生認識を比較元とする。

原5資料と凍結済みJPEG90/75/半分PNGの15変形を全件使用し、DEIM/bandsの両方で比較する。
幅/高さが実際のモデル入力比率を超える横書きcropだけ、既存の
`split_line_for_input` / `crop_line_chunk_rgb_u8` による元RGBの区間を認識する。
分割不能/1区間/空結果なら比較元を保つ。方向は元の横書きとして明示する。
RGBから画線を消さず、辞書/真値/文字内容で対象を選ばない。
chunkの認識を既存の空白挿入規則で連結し、平均信頼度は出力文字数で重み付けする。
元と候補の全crop座標・生/断片結果・confidence・chunkを保存する。

これはモデル入力の情報量と文脈の診断であり、通常cascadeの改善と混同しない。
比較元の全40本文を固定CLIの明示設定で別途再現し、診断の取り違えを防ぐ。
none/width/strictの画像別120文字距離で非悪化を確認し、正読の退行があれば
一律の既定化は棄却する。改善箇所だけで合算評価しない。

良い結果が得られても、通常cascadeへの導入は別の先行仕様とRedテストから行う。
単一のURLや資料に合わせた閾値調整、文字列の補完/置換はしない。

## 実入力幅までの隣接区間の結合候補（推論前）

細かい分割の初回比較では改善と退行が混在した。次はモデルを変えず、
隣接する区間を実モデルの幅/高さ比まで結合して文脈を増やす。
元APIの8倍/20列群という保守的な分割は変更せず、診断だけの別候補とする。

元座標が連続し、結合幅×入力高が行高×入力幅以下の場合に限って、
左から貪欲に隣接区間をまとめる。元の区間内の全RGBを残す。
単語境界も画像中の白紙はそのまま含め、最初の区間のspace/gap metadataを保持する。
元APIが省いた非連続の白余白を新しく取り込まず、元からモデル幅を超える単一区間は
それ以上結合しない。不正寸法/逆順/重複矩形はエラーにする。

純粋な例示/境界/非連続/不正入力/PBTを先にRed化してから診断用helperを実装する。
同じ20画像・2検出・100文字モデル・後処理・全120指標で比較し、退行があれば
この結合候補も一律の既定化を棄却する。条件は結果に合わせて調整しない。

## 通常cascadeと固定100文字モデルの対照（全比較前）

固定100文字モデルの全40本文がCLIで再現できたため、同じ20画像・2検出設定で
現行の通常cascadeとも全件比較する。native分割候補とは独立に採点し、全120指標の
画像別非悪化を要求する。画像ごとのモデル選択は行わない。
ここまでの100文字モデルの全730cropは認識長77文字以下で、長行splitの80文字閾値には
達しない。単一モデルでよいという結論を既定CLIの一部の例だけから出さず、
退行があれば全100への置換も棄却する。性能や未知資料への優位性は別途扱う。

## 結果：3案とも一律の既定化を棄却

固定20画像・2設定の全730cropを認識し、全幅比較元40本文が明示設定のCLIとbyte一致した。
生認識前の全幅結果の本文/confidenceも2回の診断で730件すべて一致する。
対象410領域中402を分割でき、細かい案は2168chunk、実入力幅の結合案は804chunk。

120画像別文字指標のうち、細かい分割は63、実入力幅の結合は30で悪化した。
全100文字モデルへの置換も15で悪化し、3案とも既定化を棄却する。
元画像の神戸市DEIMは全幅100で生66字、細分割74字、結合69字。
元の気候資料では生距離が改善してもstrictが悪化する例があり、単独指標で採用しない。

結合helperは未実装Red→例示/境界/不正入力/被覆PBT 5件Green。
診断2設定と40 CLI実行が成功。fmt/diff/対象Clippy成功（既存17警告、変更箇所に新警告なし）。
製品コードは変更していない。出力/真値/全18採点/コマンド/SHAと再生手順を
`benchmarks/page-chunks/` に保存した。初回の全幅rawだけは、同一の本文/confidenceを
確認した2回目のcaptureから補った履歴を明記している。

現コーパスの全幅100認識は最大77文字なので、CLI既存の80文字以上の長行再分割は
この評価に含まれない。次はこの分岐の固定真値と入力を追加し、中央で字形を切る
可能性を切り分ける。今回の棄却を全ての区間分割が無効という結論にはしない。
