# 長い縦列の支持maskを大津の二値化で作る別案

## 純粋テスト・実装・新しいmask生成・追加NN前の仕様

前案docs/vertical_model_capacity_recovery.mdは、色背景の準備後にも微小画素が字間をつなぎ、
9列/27組の全件で40groupへ届かなかった。追加NNと製品接続は行っていない。
その条件や結果を上書きせず、支持maskの生成だけを変更する別案をtest-onlyで調べる。
原RGB・モデル・原文/辞書・後段の容量/group/出力/空白の条件は変更しない。

### 二値化の定義

[OpenCVの説明](https://docs.opencv.org/4.10.0/d7/d4d/tutorial_py_thresholding.html)と
[scikit-imageの説明](https://scikit-image.org/docs/stable/auto_examples/applications/plot_thresholding_guide.html)
にある、大津法のクラス間分散を最大化する定義を使う。新しい画像ライブラリ依存は加えない。

- 原cropを既存の無補間回転で得たRGBから、灰度g=floor((R+G+B)/3)の256binヒストグラムを作る。
  前案の色背景準備の出力からではなく、元の回転RGBから推定する。
- n=全pixel数、S=全灰度和。t=0..254について、w=灰度t以下のpixel数、s=その灰度和とし、
  0<w<nの場合の `(S*w-s*n)^2 / (w*(n-w))` を比較する。これは最大化目的に関する定数を除いた値。
  同点では小さいtを採る。灰度g<=tを黒、他を白にする。
- 空/単色ヒストグラムには有効な二分割がなく、候補なしとする。checked u128で積/和を扱い、
  表現不能なら候補なしとする。分数比較は交差積でoverflowさせず、整数商と剰余を使う。
  f64の丸めで同点の閾値を移動させない。
- 出力は支持用の0/255 maskだけ。NN用RGBは元の回転画像のままで、maskを認識へ渡さない。
  濃度補間・形態処理・小成分除去・字種/書体照合を追加しない。

### テストと凍結

- 2濃度、単色/空、均等256濃度、非対称分布、同点とoverflowを例示する。
  整数分数比較は安全な小さい交差積とPBTで照合し、ヒストグラムの重みの正整数倍と
  飽和しない灰度平行移動で閾値の対応が不変になることも64例PBTで検査する。
- 元RGBとmaskの分離を前案の例示/PBTで再確認する。新しい候補へmaskを流してしまう
  回帰を検出することを優先し、同じpixel値の保持を確認する。
- 純粋Red→Green後に同じ全9検出列を再監査する。別のPython実装はFractionによる有理数で
  t=0〜254の全閾値を走査し、Rustの閾値/maskと比べる。全原回転/chunkを元RGBへbyte照合する。
- 前案の全27組/72chunk・source/binary/失敗ログを保持する。到達性は精度と区別し、
  maskや閾値を追加NN結果へ合わせない。次の追加実資料/非文字対照は認識前に別途固定する。
- 到達性がなければ追加NNを行わない。製品接続は実モデルRedと全ページ/既存縦横対照の
  入力別none/width/strict文字・単語非悪化が確認できた場合だけとする。

この仕様時点では新しい閾値/maskも分割認識結果も未測定で、製品の改善は未採用である。

## 幾何だけの結果（上記仕様を凍結した後）

純粋12テスト（4つの64例PBTを含む）が成功した。独立Python Fractionによるt=0〜254の全閾値の走査と、
9列すべての閾値/二値maskが一致した。元回転RGBと3形状別81chunkも原座標へbyte一致した。
H1の記録処理を共有するrefactorは、旧91ファイルのbyte一致を実行で確認した。

既存の数値条件を変えず、幾何/原結果長の到達性が30モデル4組で成立した。
閾値は164〜172、支持groupは38〜47だった。これは認識結果の回復を意味しない。
分割認識・出力選択・製品接続は未実施。追加対照はdocs/vertical_capacity_controls.mdへ先行固定する。
