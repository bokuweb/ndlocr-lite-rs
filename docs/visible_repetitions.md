# 画像の画線群で支持された反復文字を保持する

## 実装前仕様

先行診断は `docs/repeated_glyph_diagnosis.md`。生の正読が従来sanitizerで削られるが、
無条件の制限解除は誤読も増やす。ページの行/chunkに限り、以下の条件で反復制限を省く。
単行/public sanitizer、公開Poolの標準モード、生出力、モデル/方向/信頼度は変えない。

- 既存の空白整理・括弧方針・共通置換を保持し、反復制限だけを省いた候補を作る。
- 候補が従来結果より長く、空白のない1連続の文字列である場合のみ画像を調べる。
- 実際の前処理が横方向の場合のみ。Autoで回転する縦入力には適用しない。
- 220前景の8連結成分を測る。面積3未満を除き、最大成分高を基準に面積が
  max(3,ceil(最大高/2))以上の成分を有意とする。
- 全有意成分は最大高の3/4以上の共通した縦範囲を持ち、各幅は最大高の2倍以下、
  左から並べたbboxの横範囲は重ならない。異なる行・接続画線・大きな追加図形を支持に使わない。
- 有意な画線群の数と候補のUnicode文字数が完全一致する場合だけ候補を採る。
  それ以外や不正なRGBは既存sanitizerの結果を保持する。

文字種類/語句/真値からの補正はしない。反復の追加分は同じモデルの生出力に元々存在する字の保持だけで、既存の共通置換は維持する。
画線群の数は文字の意味を保証せず、原モデルの文字種誤読は解決しない。
画像は変更せず、追加推論も行わない。最初はprivateな独立処理として診断全件で検証し、
実モデルと全287画像×6経路×3正規化を通過してから通常ページ経路へ接続する。

先に複数の反復文字/混合pattern、数不一致、ノイズ/罫線/接続成分、2行、非横方向、
RGB不正、空白/括弧互換、閾値境界、拡大/移動/色のPBTをRed化する。
後処理の制限を省く関数を既存関数から共有し、既存public APIの挙動は変えない。

## 画像を持つ単行APIにも適用する（拡張前）

独立診断で204の正読欠落を画素支持で保持でき、全2772文字指標は非悪化だった。
ページ用Poolの実モデルRed2件もGreenになった。しかし同じ画像を持つ単行APIや
Pool標準モードでは依然として正しい6桁を4桁に削る。既定APIの互換性だけを優先して
この既知の欠落を残すことはせず、画像を受け取る認識APIすべてで同じ画素支持を使う。

最初の仕様の「単行/公開Poolの標準モードを変えない」はここで改める。
テキストだけを受け取るpublic sanitizerと生出力APIは従来どおりとする。
単行認識は従来の括弧削除方針、ページ断片は閉じ括弧保持を維持し、反復部分だけを画像で支持する。
括弧を除いた最終出力文字数ではなく、生出力を空白整理した全字形数と画像を照合する。
認識方向・confidence・エラー・session再利用・batch順は変更しない。

先に単行stateless/Session/Pool/Session batchの6桁保持をRed化する。
既存の「旧APIは4桁」という回帰は、text-only sanitizerの互換を検査しつつ、画像付きAPIは
6桁と反復patternの真値を保持する仕様へ変更する。実画像を持つAPIの出力改善であり、
raw候補列や文字集合・テンソルAPIから文字数を推測して追加することはしない。

単行CLIは新160画像に、既存の単行素材と白紙/図形対照103画像を加えた計263画像で、
30/50/100の全3モデル×none/width/strictを別途比較する。beforeは11b6118の固定binaryで実行する。
ページ6経路の全5166文字指標と合わせ、全7533画像別文字指標の非悪化を採用条件にする。

## 単行CLIの出力フレーミングを分離する（採点修正前）

最初の単行CLI比較はstdout末尾の `println!` のLFを本文予測へ混ぜたため、
たとえば真値`OOOOOO`に対する`0000\n`→`000000\n`を6→7誤りと数えていた。
認識本文だけなら6→6で、CLIの期待stdoutも`OOOOOO\n`とするのが正しい。
この不整合を不採用結果として保存し、画像/元のliteral truthは変えない。

全stdoutの元byteとSHAを`.stdout`へ保存し、`.txt`には終端LFを厳密に1個除いた内容を置く。
終端LF欠落/複数LFはエラーとし、他の先頭/末尾の空白・CR・Unicodeなどはそのまま保持する。
before/afterへ同じ規則を適用し、全予測で`content + LF == stdout`を検査する。
単行CLI用stdout真値はliteral truth + LFとして別に記録する。再推論や原文の調整はしない。
失敗する空/不正フレーム・UTF-8/空白保持のテストを先に追加してから抽出関数を実装する。
