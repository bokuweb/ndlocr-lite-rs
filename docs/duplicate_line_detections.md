# 異なる行クラスの競合検出による本文重複

固定公式DEIMモデル（`docs/upstream-assets.json`）で、既存の
`tests/fixtures/noisy_line_gaps/mixed_height.png` の通常本文2行が
`line_main` と `line_title` の両方に検出される。
上段は `[42,28,262,56]`、下段は `[42,88,262,115]` で競合し、
現在の認識経路は4回認識して同じ本文を二重に返す。
大見出しは `block_fig` と誤分類されており、この問題の修正対象とは分ける。

## 先に固定する振る舞い

- 認識前に `line_*` の候補を選ぶ共通処理を導入し、異なるクラス間で
  IoUが90%以上ある候補だけを同一行の競合とみなす。
- 信頼度の高い検出を残し、同点では入力順の先頭を残す。
  残した検出の座標・信頼度・文字数・クラスをそのまま使い、元の順序を保つ。
- 同一クラスの候補、離れた同じ本文、部分的な重なり、包含された小領域、
  非行クラスを根拠に本文を削除しない。座標不正/非有限信頼度の候補は
  重複判定に使わず、各呼出元の既存の検証に渡す。画像外の座標も抑制の根拠にしない。
- CLIのcrop準備、cascade接続、再利用PageRecognizerの3経路で共用する。
  生のDEIM検出結果は保持する。ページの検出総数は生の件数、
  認識行数は選択後の件数とする。
- 整数演算の境界、縦書き、拡大・移動・順序反転をユニット/PBTで確認する。
- 実モデルで4候補→2 cropと、従来/キャッシュ検出の一致を検証する。
  原文は画像通り `通常の本文です。` 2行と `二三ごニニ` とし、
  見出しの脱落を評価から消さない。モデル・文字集合・閾値は変更しない。

90%は同一領域に近い競合だけを対象とする保守的な条件であり、
未知資料での汎化、全文CER/速度改善、大字形の検出回復を保証しない。
公式PythonのDEIM wrapperにも実行されるNMSはなく、upstream revisionは
`d001dad2013ceabb5736ff8d637474e443eb73c2` のまま。
