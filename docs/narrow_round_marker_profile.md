# 狭い丸括弧の支持用profile

## 実装・追加認識前仕様

比較元は1ec730a。先行監査の幅4px/高さ19pxの `)` は、本文高20pxのH/4幅境界で拒否される。
上端/下端が左、中央が右へ張り出す19行の形状を観測した。まずtest-onlyでmark単体を扱う。
従来のH/4判定や本文分離・所属条件を変更せず、製品へ接続しない。

- 元RGB和660の前景を使い、bboxが画像内にありRGB長が正しいことを確認する。元画素を変更しない。
- 本文高をHとし、mark幅はmax(3,ceil(H/6))以上、ceil(H/4)未満。mark高はceil(3H/4)以上、floor(5H/4)以下。
  幅だけの救済を行わず、以下の全形状条件を必要とする。
- bbox内の前景数が元mark面積と一致する。全行が空でなく、各行は1つの連続区間で、長さはceil(3*幅/4)以下。
- 最初と最後の行の右端は、bboxの左ceil(幅/2)列の中にある。
- bbox中央行を含む連続帯で、各行の左端が左floor(幅/2)列より右、右端がbbox右端に一致する。
  この帯がceil(mark高/3)行以上あること。単なる直線・斜線・corner・左向き括弧を支持しない。
- bbox全行・面積・端・中央帯を検査する。都合のよい行だけを切り出さず、文字内容や単語を推定しない。

既知の丸括弧とcornerを先にRed→Greenとし、矩形/細線/斜線/左向き/短い中央帯・空行・分断行、
余計な内部画素・面積不一致・不正bbox/RGB、幅/高さ/帯長の包含境界を小さなテストで追加する。
mark単体の紙・移動・灰度・整数拡大の性質を検査する場合も、本文1画素bridgeの拡大不変とは扱わない。

profile通過だけでは採用しない。本文と組み合わせる前に別途仕様を先行し、空白なし3字・端のround closer1個・
表示幅2の本文2字・前段と同じ全画素所属/1画素接触/左右groupを維持する方法を検証する。
全保存137,991組の比較と、新NN前に固定した対照（実空白/余白/圧縮/非文字と逆向き・直線形状など）を必要とする。
全群・全正規化の文字/単語指標に悪化があれば棄却し、同じNN結果へ数値を合わせ直さない。
未重複RGBへの追加NN適用と非悪化が確認されるまで、製品接続や精度改善・汎化の主張は行わない。
