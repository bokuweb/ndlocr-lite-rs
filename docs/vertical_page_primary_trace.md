# P1: Page認識直前の実入力と分割棄却の固定診断

## 事前仕様

73e9ab4のOは直接Fragmentで9画像を改善したが、444 Page IDの本文と平均confidenceは全経路で不変だった。
P0は新規144画像・864 Page結果の返却枠を再構成しただけであり、実入力との同一性をまだ証明していない。
したがって検出枠を広げたり分割閾値を変える前に、同じ全144入力を除外せず観測する。

- N/N2の各72入力、計144（本文108、空GT診断36）を固定する。全model30/50/100 × eval/defaultを実行する。
- root製品コードは変更せず、73e9ab4と同じRust sourceの隔離コピーにcfg(test)限定の記録を加える。
  Cargo.lock、モデル、charset、入力PNG、仕様、コマンド、ソースとバイナリをSHAで固定する。
- Pageの最初の一括認識へ渡す各cropのRGB/寸法/bbox/using_bandsを記録する。
  raw復号直後とH/Oの適用後・sanitizer前を記録し、元rawと最終Page本文を混同しない。
- Oが呼ばれた各入力についてplans成立/不成立、両分割の境界、各Horizontal raw結果（またはエラー）、
  combineの採用/棄却を保存する。新しい閾値・再認識経路・文字置換は一切導入しない。
- actual PARSeq session.runの試行を記録し、成功/失敗と区別する。Page API呼数、モデルload数と混同しない。
- PNGまたは可逆圧縮RGBから独立PILで実crop画素を照合する。元glyph bboxの部分交差/枠外を残す。
  返却枠と同じ場合だけproxyとの一致を記録する。欠けた字形を除外して分割安全と主張しない。
- 全864 Page出力を以前の73e9ab4候補結果とtext/順序/bbox/confidence bitsで比較する。
  記録によって結果が変化した場合は診断を失敗とし、製品改善として扱わない。
- 記録器の無効時no-op、実バイト/順序の保持、drain後の無効化をRed→Greenで先に検証する。
  一般製品テストとしてrootへ記録器は追加しない。

この既知入力による原因診断はholdoutではない。次の政策を採用する場合は別仕様・新規対照、
全既知入力の無回帰とPage/CLIでの実改善を必要とし、P1の結果だけでは採用しない。
