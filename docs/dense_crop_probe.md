# 高密度長行のcrop後の復旧失敗を分離する

## 実装前の診断方針

e9b1bd3の全幅ROI診断では120字和文4例が同モデル100のchunkで完全一致するが、
bands cropの36px2例は短いまま残る。閾値や真値を調整する前に、入力の差を特定する。

固定79画像を全件使い、元画像/bands/DEIMの準備済みcropを記録する。
各入力の寸法、bbox、重複判定、220前景の列数/支持列群/本文高、元100認識と停止理由を保存。
入力比率の2倍より横長・16字以下のcropは既存chunkへ分け、同じ100モデルの生結果、
停止理由、信頼度、境界を全件記録する。各cropの余白と最初に失敗する条件を分ける。

候補の追加実験は、結果を見る前に固定した上下白余白（0、1、2、4、8px）を
全該当crop/chunkで比較する診断のみとする。前景は消さず、内部語句や真値を選択へ渡さない。
通常製品コード・デコーダ閾値は変えない。一律余白の既定化はこの診断だけから判断しない。

有効な一般条件が見つかれば、別の先行仕様と失敗テストから実装する。
採用は現在の79画像×4経路×3正規化全948文字距離の非悪化を最低条件とし、
新たな独立対照も必要に応じて先に固定する。単語指標も全件報告する。

## 追加対照の先行固定

診断結果を読む前に、新規の独自和文/英文、未使用の細いW2/太いW8、20/40px、
上下余白0/6pxを描画する（16 PNG）。余白0の8例にはJPEG75も加え、計24画像。
truthは文章そのもの、末尾改行なし。font/Pillow/画像/truthのSHAを固定する。
既知の79画像とは別に全件比較し、正読する余白ありの対照も保持する。
この字体変種も合成開発対照であり、独立実資料とは称しない。

## 診断の記録範囲と結果

全79画像で元画像/bands/DEIMを走査し、モデル比率2倍超・高12px以上に該当する
36画像の88領域だけを詳細PARSeq記録した。全入力の寸法/検出枠の索引は別のinventoryへ保存する。
初回16字以下だった79領域で5余白条件を比較し、chunk6470回＋全幅88回を記録した。
79領域は79の独立画像という意味ではない。

36pxの2例はいずれも幅25pxの読点だけが独立し、他の本文は正読だった。
上下余白を0/1/2/4/8pxへ変えても読点は `...` / `1.` / `0.` 等となり解消しない。
全固定79領域でも、0pxに対して1/2/4/8pxの各案は12/13/9/11領域の生文字距離を悪化させた。
比較は同じcrop同士で全文truthへの距離を数え、DEIMの切り落としも除外しない。
これは診断chunk連結の比較で、既定CLIの全件A/Bではない。一律余白は採用しない。

同じ画素で小画線を前後のいずれかのchunkへまとめる診断は、30/100モデル×2字体×2方向の
全8条件で全文120字の完全一致。モデルや閾値は変えず、画像の文脈を直す候補を
別仕様 `docs/isolated_trailing_mark.md` と先行Redから実装する。
