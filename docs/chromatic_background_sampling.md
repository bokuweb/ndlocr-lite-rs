# 色文字で背景推定が汚染される境界（2026-10-17）

初回推論前に正解147文字・2行と原寸画素/SHAを固定した、独立したcharacter-formatting.pdfの項目3–4を使用する。出典は `tests/fixtures/independent_chromatic_formatting/source.json` とomoの評価記録。項目1・2・5やPDF全体の精度は評価しない。

公開d0b71d8では緑背景の紫文字の行 [40,169,1621,224] が分割不能となり、領域全体がEngineFailure。背景は[152,251,152]、文字は[72,61,139]。文字も有彩色であるため背景標本へ入り、縦に長い画線が列中央値を占めて文字を消し背景を黒くする。また密な水平画線が行の明度中央値を変え、短い行帯に分割された背景が未処理で残る。

実装前のRed:

- 原寸2行を検出し全行を安全に分割するテストは失敗。
- 縦の過半数を覆う色文字で背景白・字形暗を要求する合成例、等明度の成分交換・拡大/位置ずれ・字形高さPBTが失敗。
- 横の過半数を覆う3行の色画線で、背景白・字形暗を要求する合成例も失敗。

背景標本は横に長く色が滑らかな連続区間からのみ取得する。隣接RGB成分差が24以上なら区間を切り、既存の幅1/4かつ64列以上の支持条件を維持する。列RGB中央値から字形の混入を除き、行帯の分割と開始は長い背景区間がある行だけで判断する。行明度中央値そのものは維持する。無彩色ページは借用のまま。モデル、辞書、文字列置換、推論数は変更しない。

棄却: 隣接色の正規化比による区間判定、および連続標本だけの行明度中央値は既存gradient headerを壊す。
