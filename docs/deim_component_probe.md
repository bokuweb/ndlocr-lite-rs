# DEIM crop の四辺成分回復の診断

## 事前固定する比較

最新の通常 `prepare_line_crops` が返す全領域に対し、既存の明示 API
`complete_clipped_band_components` を閾値220、最大拡張24pxで一度呼ぶ。
通常経路は変更しない。原5資料と `deim-edge/quality` の固定15変形を全件使う。
24pxはモデル入力の高さに合わせた診断上限であり、資料ごとに調整しない。

変化する領域だけ同一PARSeq session、原RGB、生decoderで前後を比較する。
50文字と100文字モデルの両方を記録し、候補に都合のよいモデルだけ選ばない。
検出生値、元領域、候補領域、全文、平均信頼度を保存する。
診断は最終CLI評価ではなく、crop欠損と認識感度の原因分離とする。

## 採否

正しかった字形を壊す場合は、この広い回復条件を既定経路へ採用しない。
改善候補は原画像の画素で原因を確認し、汎用的に区別できる条件が見つかった
場合だけ別の仕様・Redテストから実装する。本文、辞書、truthを選択条件に使わない。
JPEG/縮小も既知資料の変形であり、未知資料への精度保証には使わない。

## 結果：既定化を棄却

20画像の全368領域中219領域が変化し、50/100の438モデル対を比較。
全文が変わった対は66対。これはモデル単体cropの診断で、
CLIのカスケードや長行split後の精度差として合算しない。

原NDLロゴの[1,0,598,64]を右へ2px広げるだけで、100文字モデルの正読
「国立国会図書館」が「館書図会図書館」へ崩れた。
原NDL本文では50文字モデルの「アクセシビリティ」が「アクセシピリティ」へ
変化しながら平均信頼度が0.976→0.994へ上昇した。
原気候資料では「2.8」が「28」になる例もある。信頼度による単純選択も採用しない。

一方、神戸市の「開覧」→「閲覧」等の改善は、回復した境界文字ではなく
内側の文字に生じており、入力寸法によるモデル感度の影響を分離する必要がある。
規則の一律既定化や資料別の調整はせず、現行の短い横画線だけの回復を維持する。

固定値・入力/model SHA・全生結果・実行ログは `benchmarks/deim-components/`。
別途確認した気候資料の「℃」「°」は、現行モデルの実文字集合に含まれない。
文字集合へ追加するだけではモデルの出力クラスと対応しないため、crop施策とは分ける。
