# DEIM行cropの先頭薄画線を診断する

## 実装前の仕様（2026-10-19）

固定NDLアクセシビリティ資料の先頭は真値が「一部から成る」だが、既定DEIM CLIは
「部から成る」、帯検出CLIは「一部から成る」となる。文書固有の文字挿入は行わない。
生DEIM/選択cropの座標と元RGB、同じモデルの生出力と既存後処理を保存して、
検出範囲の欠落か、モデルが持つ画素を読めないのかを区別する。

先に既定CLIで正しい先頭を要求するRedを固定する。元画素がcrop外にある場合だけ、
既存の汎用edge-ink回復（水平の細い字形と距離/幅の条件）が使えるかを調べる。
画像内の別行・罫線・近傍ノイズを新しい文字として加えない。横書きに限定し、
生DEIMと選択metadataは保持する。候補が得られたら境界/負例/PBTを先にRed化する。

採用には同梱5資料×DEIM/bandsの全文none/width/strictの画像別非悪化と、実モデル回帰を
要求する。画素範囲の回復だけから認識精度の改善を主張しない。元RGBを変更しない。

## 観測と部分欠損の仕様（実装前）

先頭cropは[49,16,1054,40]。閾値220の8連結成分で「一」は[32,25,55,28]なので、
左17列が欠けている。50/100モデルの生出力はともに「部から成る」で始まる。
既存restore_edge_inkは元矩形と交差する成分を除くため、完全に外側の字形と異なり
この部分欠損は対象外。既存関数を広く緩和せず、DEIM由来の認識cropに限定して補う。

- 画像内の横長行（幅4行高以上、行高12以上）だけ、左右境界のインクを確認する。
- 境界列のインク全体が1行高の1/4以下で、中央から1/4行高以内にあること。
  その全画素が単一の8連結成分へ属する場合だけ候補にする。
- 行の上下を変えず、境界の内外1行高の局所窓で連結成分が完結すること。
  成分幅は1/3〜3/2行高、高さは1/4行高以下。長い罫線・背の高い字形は対象外。
- 成分の外端から2pxまでの余白を加え、片側の最大拡張は1行高以内。
  拡張領域の閾値220未満の画素がその成分だけであることを確認する。
  原RGBは変更せず、AAを含む矩形内の画素をそのまま渡す。
- 元領域が他の選択行と重なる場合、拡張後に他行と衝突する場合は変更しない。
  既に重複する領域を自動的に「安全」と判定しない。不正RGB/座標も拡張しない。
- 生DEIMと選択metadataは不変。認識領域だけを広げ、CLI/cascade/PageRecognizerで共用する。
  既存のpixel-aware選択の後、明示crop-paddingの前に実行する。

元の帯検出関数は変更しない。ただしCLIのbands fallbackも共通crop準備を通るので、
実際の出力が変わらないことを全件評価で確認する。完全欠落して接続しない字形、
文字/同形図形の意味分類、全てのAAやJPEGにおける回復は保証しない。

## 画質変形による追加対照（推論前）

5つの元資料で候補を変更せず、JPEG品質90/75（subsampling=2）と、各辺を1/2へ
Pillow bilinearで縮小したPNGを全件作る。計15画像の真値は元資料と同じにする。
変形後にモデル結果を見て画像を選別しない。各画像×DEIM/bandsそれぞれで
none/width/strictの文字距離非悪化を追加ゲートとする。失敗すれば候補をそのまま採用しない。
これは既知5資料の変形回帰であり、独立の実スキャン/未知資料や全JPEGの保証とは区別する。

## Red / Green と最終比較

既定CLIの先行Redを確認。合成/cascade/PBTの3 Red→4 Green、提案矩形同士の
余白衝突を保護する追加1件もGreen。実画像は[49,16,1054,40]→[30,16,1054,40]へ
横方向だけを拡張し、50/100両モデルで先頭「一」が戻った。PageRecognizerの100文字モデルも
同じ認識領域と正しい先頭を返す。生DEIMのJSONは前後で同一。

元の5資料×2設定×2版の20プロセスが成功。NDLのDEIMだけ生60→59、width53→52、
strict11→10/1058字。他9組の本文はbyte同一で、全30文字指標が非悪化。
追加15画像×2設定×2版の60プロセスも成功し、全90文字指標が非悪化。
NDLのDEIMはJPEG90で生62→61、JPEG75で85→83。後者はモデル出力の「書箱」→「書籍」も
改善し、文字列置換は行っていない。他28組の本文はbyte同一。半分解像度での改善はない。

通常回帰486件が成功し、その後追加した境界1件も含む構造テスト5件が成功。
実モデルを含むONNX構成395件、回収を使うNDL資料での既存ページ並列1件も成功。
fmt/diff、対象Clippy成功（変更箇所以外の既存17警告）。通常とONNXのビルドは順に実行した。
全実行条件・frozen画像/真値・hash・生本文は `docs/benchmarks/deim-edge/`。

JPEG対照は同じ5資料を機械的に変形したものなので、独立の実スキャンや未知資料への
汎化とは扱わない。別のノイズ/同形図形との意味的区別、切り離された完全欠落文字、
幅広い字形や背の高い字形、縦書きの回復、速度・総推論数の改善は未確認。
