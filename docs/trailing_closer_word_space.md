# 末尾閉じ括弧の直前の空白を画線から確認する

## 診断後・候補実装前仕様

`closer_word_spaces_probe` でfc22d35は新しい空白対照7本文組・14単語指標が旧厳密支持版より悪化した。
印字 `ABC 』` にraw `ABC』` が出ると、閉じ括弧の回復で文字は改善するが単語は1→2となる。
退行を隠さず、空白の支持を追加する。prefix・内部・複数closerや非ASCII空白はこの小ステップでは現行を維持する。
未回復289組や他の空白問題を完了扱いにはしない。

候補は、既存の括弧除去結果よりfragmentが長く、実効Horizontal・有効RGBのときだけ確認する。
末尾1個だけが既存5種closerで、本文3字以上、本文にwhitespace/他closerがなく、末尾前のASCII空白は0/1個に限る。
空白を除く文字列と独立成分数が一致しx重複がなく、従来または本文整列の支持があることを先に要求する。
本文の隣接成分から2個以上のreference gapを得て、各gap>0かつ4*max_gap<=本文最大高さを満たす場合だけ使う。
細い罫線や極端に高い画線を空白の根拠にしないため、closer幅>=ceil(本文高さ/4)、closer高さ<=本文高さ*2を要求する。
末尾gapが max(2*reference最大+ceil(本文高さ/8),ceil(本文高さ/3)) 以上、かつ本文高さ以下なら
1個のASCII空白が支持される。この式は候補評価前に固定し、grid探索しない。
支持があるときだけ元本文＋ASCII空白1個＋元closerを選択する。不確かなときは現行fc22d35の結果を維持する。
語句やcloser種類の推測置換はしない。追加モデル/forwardなし、RGB/confidence・text-only/raw/候補APIを保持する。

まずtest-only候補を純粋Red→Green、閉じた境界・弱いreference/細罫線/遠すぎる画線・RGB/方向・PBTで検査する。
末尾gap11〜12、reference1〜3の最初の80画像は探索用であり、独立holdoutと呼ばない。
候補の結果を読む前に、本文 `DEF`、丸ゴシックW4/角ゴシックW3、20/40px、5 closerのprefix/suffix・空白0/1・
PNG/JPEG75の160画像を固定する。別にDEF＋右縦罫線（幅1/2・gap2/10・高さ22/66・2形式）の16対照を固定する。
truthは描画文字列（罫線は文字に含めない）、後から変更しない。全176のfixture Red→Greenを先行する。
既存1351＋追加176=1527×3モデル×3正規化=13743の文字/単語指標を正式toolで比較する。
現行fc22d35比の非悪化と、新空白対照で旧厳密支持より増やした単語退行の解消を要求する。
追加対照は既知fontの合成開発対照で、未知実資料のholdoutではない。
候補が通っても、製品適用には別途実API/CLIのRed→Green・全件比較を必要とする。

罫線対照のcanvas幅は高さの2倍以上とし、Auto回転だけで候補が除外されないよう固定する。
