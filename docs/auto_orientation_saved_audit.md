# Auto方向と原Horizontalの保存結果の監査

## 実装・採点前仕様

分離部品phaseまでの製品変更を先に完了する。本監査は新しい製品処理を追加せず、
既に認識・保存した方向比較だけを正式scorerで定量化する。
1画素phaseの128画像と分離部品適用対照の64画像は、いずれも横組みの原画像が
紙を含むcanvas高さによってAutoで反時計回りに回転したもの。
各画像・全3モデルのrawをAutoと原Horizontalで対にし、none/width/strictの文字/単語距離を全件比較する。
新規NN、未知方向のholdout、一般的なHorizontal優位性の証拠とは数えない。

- Pairingを先にテストする。ID重複、モデル出力欠落/余分、真値不一致、原RGB SHA不一致、
  回転条件不一致を拒否する。両条件は同じ原RGB/寸法で、forward形状だけが異なることを確認する。
- 原Auto=有効Horizontalの前処理tensor bit一致は前段の保存検査を参照する。
  順番が違ってもIDで対にし、空文字や端/内部空白を一切stripしない。
- 全192原画像×3モデルを採点する。本文のみ/線/点等を含む全回転対象を保持する。
  文字/単語悪化、同点、完全一致回復を分け、別母集団の改善を合算しない。
- 改善があっても方向処理へ即時接続しない。次の仮説は真の縦組み・短い文字列・
  複数部品・紙/枠/ノイズと明示Vertical/Horizontal指定を含む新対照を、追加認識前に固定する。
  RGB前処理と後処理の両方で同じ向きを用い、raw APIの契約と既存ページへの影響も別途検証する。

## 保存結果の監査結果

Pairingの4テストをRed→Greenで確認し、正式scorerで36表ファイルを生成した。
原横組み192画像×3モデルでは、生文字距離総和1,902→196、単語距離576→188。
生完全一致回復388組で、文字距離574改善/2同点、単語距離388改善/188同点だった。
none/widthでは文字/単語悪化0だが、strictで100モデルの文字距離が2組悪化した。
Autoの誤読の文字数/記号がたまたま近い例も含め、これを退行0と表現しない。これは既に保存していたrawの比較で、新規NN forwardは0。
既知の横組み・同fontの、Autoで回転した部分集合だけの監査であり、方向識別の汎化を示さない。
全入力/出力SHA、正式採点表、Red/Greenとpairing実装は後続の方向改善packetへ保存する。
