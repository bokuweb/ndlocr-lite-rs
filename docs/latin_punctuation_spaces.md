# 英字句読点の後の実空白

英語記事の未調整ページを初回推論前に固定した評価で、`Discord, Dropbox` と
`Meta, and` の実空白が欠落した。原寸行ではコンマの幅7px・高さ11px、
行高46px、代表字幅19px、次の本文までの白列17pxである。
小画の左右余白6pxを単独で差し引くと、実空白を11pxと過小評価する。

英字の低い句読点は、両側が小画である隣接記号間の余白だけを補正する。
片側が本文なら、小画の幅だけから文字advanceを推定しない。
和文字形・全高の細字・疎な全高字形に対する既存の余白判定は維持する。
認識文字の置換やUnicode正規化は行わない。

実装前に原寸の2空白の属性と固定PARSeqの全文一致をRedにする。
整数倍拡大・左右余白変更でも単語空白と全画素被覆を確認する。
既存の引用符とピリオドの隣接、和文・スキャン・全文の回帰を確認する。
記事全文は合字も含む厳密なUnicode距離で評価し、開発データとして扱う。

## 確認結果

変更前の原寸2空白と固定モデル全文一致はRed。変更後は両方を保持する。
拡大・左右余白24ケースは、実空白内で分割する場合の属性と全画素被覆を検証する。
空白を含む区間を分割せずモデルへ渡すことも正当なため、分割位置そのものは要求しない。

全体回帰で疎な和文字形の反転画像が失敗したため、小画の補正条件だけを制限し、
全高字形のopen bearingの処理を維持した。発見したPBT seedも保存する。
英語記事全文は32→30/2269（31行）。既定の256幅モデル・文字集合は変更しない。
384/768幅は変更前pipelineで各23/2269、変更後は各21/2269だが、既存の和文・孤立英字で悪化する。
未知文書の一般化、残る引用符・数字・合字の誤認識、速度評価は未達。

通常テスト227件・ONNX対象164件成功。全target Clippyは既存警告のみ、fmt/diffも成功。
omoのローカル連携116件成功。既存全文・領域の誤り数は維持した。
