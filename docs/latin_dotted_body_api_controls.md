# 点付きLatin候補の公開API/CLI対照の事前選択

## 追加NN・選択実装前の仕様

全19,440追加条件と元Horizontal全件のraw比較・入力別採点は省略しない。
公開API/CLIの追加実行は、元RGB/rawから決定的に分かる後処理の変更箇所へ集中する。
全noise条件を同じNNへ何度も通す代わりに、以下の324 Auto対照を**raw取得前**に固定する。

- noiseを (engine,palt,font,size,shape,format) の324群へ分ける。
  各群でUTF-8のidのSHA256が辞書順で最小の条件を1件選ぶ。同一SHAはid順で解決する。
  本文・字間空白・前後・gapの選択はこのhashだけで決まり、認識結果を使わない。
- モデルは同じid SHA256の先頭1 byteを3で割った余りで30/50/100へ割り当てる。
  均等件数とは仮定せず、実際のモデル別件数を保存する。
- その条件がAuto回転する場合は、同じ原RGB・同じモデルのHorizontalも加える。
  全群の非欠落/一意性をテストし、同じ条件が複数回入らないことを確認する。
  入力リストの順序を変えても選択は同じである。
- id重複、324群の欠落、余分なengine/font/size/shape/formatは拒否する。
  idのSHAと選択全件のRGB/真値SHA、方向とモデルを選択記録へ保存する。

この固定対照へ、既存と追加の**変更全件**をモデル/方向別に加え、重複をまとめる。
公開Session/Poolのraw/本文/f32 mean bitを保存rawの期待値と比較する。
同じ全件を実CLIへ渡し、stdoutの末尾LFを正確に1個だけ除いて比較する。
新規NN forward、API検証のNN呼出し、CLIプロセス数は分けて記録する。

全保存rawの実製品再生は引き続き全件行う。固定対照の件数削減は、画像/正解/raw/正式採点の
条件削減や未知資料への汎化の根拠にはしない。モデル/方向/重複RGBを独立標本と数えない。
