# 密度検出で曖昧な横画を勝手に結合しない

## 実装・評価前の仕様

上流相当の公開baseは `918445ac8165573b7fbd882247e2e94a6e8ea50e`。
大字形の上下の部品を結合する未採用候補を、独立した横線の2行で検証する。
通常本文の基準行2本の下に、同じ横位置の短い横線を3〜5本ずつ2行に描く。
描画元が持つ行の指定は4行であり、検出関数へ渡すのはRGBのみとする。
幅・行間・線の厚みと整数倍拡大・平行移動を変えても、4帯を保持し、
各帯の描画範囲を被覆し、naive/fastの結果が一致することを要求する。

これは表の罫線や2行のダッシュを一つの文字行に変えないための負例である。
同じ画素を「二二二」の1行と解釈することもできるため、RGBのみから両解釈を
常に識別できるという仕様にはしない。未採用候補の合成正例にも同じ曖昧さがある。
原文、ファイル名、期待行数やOCR出力を用いた分岐でこのテストを通してはならない。

先に結合候補へこのテストを適用して失敗を保存する。公開baseへ戻して成功を確認し、
実装を追加しない判断も結果として残す。大字形の候補生成を続ける場合は、
原領域と結合領域を両方残し、読み順・レイアウト等の追加根拠を評価する必要がある。
本テストは幾何の退行防止であり、OCR精度・未知文書での汎化・速度の測定ではない。
