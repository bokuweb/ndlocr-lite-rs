# 反復文字のモデル出力と後処理による欠落を分離する

## 診断前の固定仕様

前段で `111111` の文字種誤読と反復数の欠落が残った。既存sanitizerには同じ数字4字・
同一文字8字の上限と反復chunkの縮約があるため、生モデルが正読しても削られる可能性がある。
まず画像ごと/モデルごとにrawと既存fragment sanitizerの差を記録し、モデルの誤読と区別する。
真値に合わせた文字種置換や、反復の無条件復元/無条件許可はしない。

診断を読む前に、単位 `1 / 0 / 8 / I / l / O / 一 / A1`、反復数2/4/6/8/12、
角ゴシック/明朝、PNG/JPEG75の全160画像を28px・白紙余白8pxで固定する。
同じ既知フォントの合成開発対照で、独立文書や未知資料holdoutとは称しない。
画像/真値/font/PillowのSHAと描画条件をmanifestへ記録し、OCR後に真値や条件を調整しない。
PRの差分ファイル数を抑えるため画像と真値をZIPへ保存し、通常のRustテストで全件の構成・
文字数・decode寸法を検査する。評価時はSHAを確認して一時ディレクトリへ展開する。

raw診断は同じRGBの原画像と既存帯cropを30/50/100の各固定モデル・Horizontalで実行する。
各入力の寸法、raw text/confidence、既存fragment処理後text、真値との文字距離を保存する。
前段の6文字の数字/Iを含む既存短文対照も診断し、現在製品出力との対応を確認する。
製品の選択処理や単行/public sanitizerの互換性はこの診断では変更しない。

生出力が正しいのに削られる場合だけ、画像の独立した画線群で出力文字数を支持できるかを
次の実装前仕様と失敗テストで検討する。全127既存画像と新160画像をCLI 2経路・
PageRecognizer30/100の評価/既定設定の計6経路で比較し、none/width/strictを全件保存する。
採用は画像別文字距離の非悪化を要求し、単語指標と反復図形/低confidenceの誤復元も報告する。

## 最初の診断結果

原画像/全220前景を含む帯cropの924入力で、既存fragment処理は文字距離を296入力で悪化させ、
52入力で改善した。生の正読が崩れたものは204入力（30/50/100モデル各65/79/60）。
これは同じ184画像の複数crop・複数モデルであり、924独立文書とは扱わない。
無条件に反復制限を外す案は、52入力の改善を失うため採用しない。
既存24pxの6数字は原画像と帯cropで文字種まで変わり、モデル誤読も別に残る。
