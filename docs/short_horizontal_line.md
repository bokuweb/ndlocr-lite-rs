# 短い横書き行の順序診断

気象庁の固定資料で「で上昇」が「昇上で」になる残差を、DEIM領域・crop・
30/50/100文字モデルの生結果・自動回転・ページ整序へ分離する。
実画像CLIの「で上昇」保持を先に失敗する回帰として置く。
字句の並び替えや資料固有置換を加えず、原因が幾何判定にある場合だけ汎用条件を検討する。
モデル自体の誤認識なら、その証拠を残し、無条件のモデル交換は行わない。

## 原因と次の候補（実装前）

[104,902,175,924] のcropをAuto/Horizontalで比較すると、30文字モデルは
どちらも「昇上で」(0.911)、50/100はどちらも「で上昇」(0.999/1.000)。
自動回転・整序でなく、最初のモデルの順序誤りと分離できた。

既定CLIの30-bucketから得た結果に限り、次をすべて満たすときだけ再確認する。

- 非空の横書きcrop、幅/高さ2〜6倍（両端含む）。
- 認識2〜4文字、すべてUnicode英数字、有限の平均信頼度0以上0.95未満。
- 同じ元RGBを50/100モデルで最大1回ずつ認識。50時点で採用不能なら100を省略。片方が欠落/失敗したら元結果を維持。
- 両候補が全文一致し、各信頼度が有限・0.98以上1以下かつ元より0.03超高い。
- 元とは異なる順序で、Unicode文字の種類と個数は完全一致する。

本文を並び替えて生成しない。100モデルが実際に出した全文/信頼度を返す。
無条件のモデル交換、幅広い本文や縦書き/記号/数字1文字への再推論はしない。
既存の単行API、ParseqCascadePool、単一モデルPageRecognizerは変更しない。
CLIでcascade無効・30/50 poolなしの場合も従来どおり。

純粋な方針テストでは、境界値・非有限値・不一致・文字増減・重複文字・
推論回数・失敗を検査し、PBTで採用時の文字multiset保持を確認する。
原5資料と固定15変形をDEIM/bandsの両設定で全件評価し、none/width/strictの
各画像の文字距離非悪化を採用ゲートとする。判定値を資料に合わせて調整しない。
速度/総推論数は別に記録し、上記の限定再推論による負荷増を明示する。

## 追加の合成順序対照（推論前）

条件を固定したまま、32個の2〜3文字ラベルを角ゴシック24px・明朝24px・
角ゴシック16pxの3条件、全96画像で直接モデル比較する。
ラベルには逆順対、数字、Latin、全角Latin、仮名、重複文字を含める。
印字bboxへ1px白紙を足した元RGBを固定し、モデルが読む前にtruthとSHAを保存する。
正解の内容や意味を候補の選択には渡さない。30→候補の各画像で文字距離非悪化を
追加ゲートとする。これは合成cropであり、未知の実資料に対する保証とはしない。

## Red / Green と採否

実CLIの「で上昇」保持Redを確認後、方針6件の未実装Red→Green。
無駄な100モデル推論を防ぐ1件を加え、純粋な方針7件が成功した。
実CLIはGreen、さらにcascade無効・50pool欠落の2設定も成功。

固定20画像×DEIM/bands×前後=80プロセスが成功。前版の全40本文を再現した。
気候資料の元画像/JPEG90だけDEIM/bandsとも2文字改善し、他36組はbyte同一。
全120文字指標が非悪化。元画像DEIMは生60→58、width49→47、strict23→21/800字。
固定96合成cropも全件非悪化（追加推論1件、本文変更0件）。
通常494件・ONNX対象404件に加え、追加の設定互換1件（実CLI2設定）が成功。
後者の実行時は診断テストも再度成功。fmt/diff成功、対象Clippyは既存17警告だけ。
原モデル結果・全文・真値・SHA・Red/Greenログは `benchmarks/short-line-order/`。

本候補をCLIに採用する。変更は実モデルの合意による順序選択だけで、
語句の置換、truthを使った選択、画像の画素加工を加えていない。
既知資料・合成対照による小さな改善であり、未知の実スキャン/全短行の正読は未確認。
追加推論が発生するため高速化は主張しない。
