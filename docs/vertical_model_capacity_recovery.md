# 検出された長い縦列の容量回復候補

## 幾何テスト・実装・追加NN前の仕様

実資料監査 docs/real_vertical_scan_audit.md で、同じ検出9列の30モデルに大きいraw欠落があった。
PageRecognizerのDEIM経路へまだ変更を加えず、まず既存の分割/支持を利用できるかをtest-onlyで
検査する。原文・book/PID/font・文字列置換を選択条件へ渡さない。

### 原画素と支持用mask

- Autoが既に回転する極端な縦長cropだけを対象にする。原cropを既存の無補間90度回転へ渡す。
  これは元Auto入力と同じ画素順であり、方向推定の新しい条件を導入しない。
- 画素補間・色補正・モデル変更をNN入力へ加えない。支持用の同寸法maskには既存の
  normalize_chromatic_panelsを使い、色の付いた紙が固定閾値の白帯を塞ぐかを検査する。
  NNへ渡すchunkは常に元の回転RGBから同じ座標で切り抜く。maskのRGBを認識へ渡さない。
- 分割には既存split_rotated_vertical_column_for_inputを使う。数字の内部白帯の保護と、
  縦列に単語間ASCII空白を追加しない規則を維持する。失敗や不明瞭な分割は元結果へ戻す。

### 最初の候補の制限

新しい任意の閾値を実資料の誤りへ合わせる代わりに、既存dense horizontal recoveryの制限を
初期案として共有する。回転後のheight>=12、原結果<=16 scalar、モデル容量の2倍を厳密に超す幅、
インク列が全幅の1/3以上、字高支持が全高の1/2以上、支持group>=40かつ>=原結果の4倍を要求する。
これらは今回のNN対照を認識する前から存在する条件である。幾何が支持しなければ候補なしとする。
既存と共有できる集計を抽出する場合は、元の横書き経路の全挙動同一をテストする。

分割は2chunk以上。全chunkの非空本文とconfidence .9以上を要求し、合計出力scalar数が
max(元結果の2倍, group数の切上げ半分)以上で、Unicodeのis_alphanumericに該当するscalarが4種類以上ある場合だけ
回復候補とする。confidenceはscalar数で重み付けした元f32平均で、元結果を再採点して置換しない。
信頼度だけでの採用とはせず、前記の画線・容量の条件も必要とする。
先行の空白削除案の退行を踏まえ、元結果と候補のUnicode空白scalar列も完全一致を要求する。
モデル内部の空白を削って合わせず、空白が増減する候補はそのまま棄却する。追加NN前に固定する。

### Red→Greenで先行する検査

- 暖色紙/白紙の長い既知画線列、短い列、容量境界、17 scalar、39 group、不正RGB/寸法を
  小さい純粋テストで扱う。既存の二・三の内部白帯、細線だけの列や過長の連鎖も維持する。
- unsupportedでNN closureを呼ばないこと、どのchunkも元RGBの同座標とbyte一致することを
  例示/PBTで検査する。maskと元画像の取り違えを検出するテストを置く。
- 低confidence/空chunk/少なすぎる回復/空白増減/エラーは元結果を保つ。複数chunkの集約を境界テストする。
- 数値条件を追加NN前に凍結する。旧9検出列だけで実装を採用せず、既存縦横回帰・全ページ対照と、
  認識前に別途固定する追加実資料/非文字対照も揃える。モデル/方向/重複を独立標本と数えない。
- PageRecognizerへ接続する前に、実モデルRed、全入力別none/width/strict文字・単語非悪化、
  新しい未観測対照での適用、元RGB/座標の不変性を確認する。退行があれば案を棄却する。

この仕様は候補の調査であり、幾何到達性や追加認識による改善をまだ測定済みとは主張しない。
初回幾何テストで前提自体が成立しなければ、その失敗を保存し、別案として設計し直す。

## 最初の幾何診断（追加NN前）

回転RGBと支持maskの分離は、暖色紙の例示Red→Greenと64例PBTで先に検査した。
次は既存監査の全9検出列にprepareだけを適用する。元RGBとmaskを両方保存し、
既存縦列splitの3モデル形状別の全chunk座標を記録する。chunkの画素は元の回転RGBから
切り抜き、別実装で元画像の対応範囲とbyte照合する。NNは実行しない。
支持group/coverageと既存raw scalar数による到達性は精度指標と区別し、候補本文の改善とは数えない。

## 最初の案の到達性（幾何診断後・追加NNなし）

全9列の回転と、3形状別72chunkが元RGBの同座標にbyte一致した。
ただし、既存の色背景準備を支持maskへ使った結果も、独立groupは6〜22であり、
先行固定した40groupに達する列はなかった。原画像の固定閾値ではgroup0だった。
原結果の長さや容量条件も合わせた到達性は全27組で0である。

この組合せを製品へ実装したり、追加NNを実行したりしない。group閾値を下げて結果へ
合わせ直さず、支持mask自体を別案として設計する。回転RGB/mask/全chunk/不成立値と、
Red/Green/PBT・source/binary SHAはtmp/vertical-capacity/へ保存した。
これは幾何上の不成立であって、分割認識の精度が悪化したという測定ではない。

## 固定候補の追加認識と製品接続前の仕様

H2と先行固定した数値条件のまま、旧9検出列・追加9検出列・余白6・図形18の計42入力を
3モデルで保存比較した。追加81回のraw Horizontal chunk API呼出し（内部forward数は未計測）で、
30モデルの旧コマ5第2列と追加コマ6第1列だけが採用された。全81chunkは元の無補間回転RGBの
記録座標と独立にbyte一致した。追加画像の初回NN前に真値とselectorを固定済みである。

noneで旧9列の誤り269→236、追加9列209→177。50/100は全件同一で、入力ごとのnone/width/strict
文字・単語距離は全件非悪化、余白・図形72組の出力は全件同一。これは同一書籍の開発対照であり、
未知書式のholdoutや製品での改善とまだ数えない。残る空白不一致候補を後から整形して採用しない。

次の小段階では、同じ凍結selectorをFragment方針のAuto認識だけへ接続する。元のraw結果を
既存の可視反復/空白処理に渡す前に判定し、採用した場合も同じFragment後処理へ渡す。
SingleLine方針と明示Horizontal経路は対象外。PageRecognizerのDEIM縦列がこの経路を使う。
既存の同じsessionを借りている間にraw Horizontal chunkを順次認識し、モデルやsessionを追加ロード
しない。元認識の失敗は既存のErr、候補の失敗は元結果を保つ。追加認識を再帰呼出ししない。

製品hookより先に、実スキャンの採用2列・空白不一致棄却列・図形安定性の実モデルRedを追加する。
その後hookのみを加えGreenへ進める。通常API・明示Horizontal・既存の全ページ/縦横対照と
追加全件API/CLIを実測し、行数/矩形も含めて比較する。退行があれば接続を採用せず撤回する。

## 製品接続の測定結果

数値条件とselectorは追加NN前の版からbyte同一のまま、実モデルRed→Greenを経てFragment+Autoだけへ
接続した。通常単行と明示Horizontalは対象外。候補chunkは同じ借用sessionのraw Horizontalで読み、
支持用maskをNNへ渡さない。元rawの空白scalar列と一致しない候補を後から整形して採用しない。

既存287画像とNDL本文6抜粋の293入力を、比較前後のAPI3モデル×2設定とCLI DEIM/bandsで新規実行した。
全7,032入力別none/width/strict文字・単語比較に退行はなく、全14,064 CSV行も独立した距離計算と一致した。
本文変更は30モデルの2抜粋×2設定の4組だけで、旧9列269→236、新9列209→177誤りへ改善した。
50/100とCLIは全件byte同一。APIの行数・矩形は全件同一で、confidence bitの変化も上記4組だけだった。
APIページ呼出し3,516回とCLI1,172プロセスを区別し、内部forward数は未計測とした。

別の既存縦書き7入力も前後全8経路で新規実行し、168文字/単語比較に退行なし、本文/行数/矩形/mean bit
すべて同一だった。既知書体/同一書籍の開発回帰であり、未知書式のholdoutや学習との非重複を主張しない。

さらに製品sourceの別コピーへtest-only記録だけを加え、全42画像×3モデル×5経路の630実API組を照合した。
raw/通常Poolは保存値、Fragment single/batch/single-session batchは固定selectorと変更していない後処理の
合成結果に、本文/f32 bitまで全件一致した。余白・図形216 Fragment経路組も従来の合成結果を保持した。

全42画像の無補間回転RGB・支持mask・閾値は独立した有理数計算と全byte一致し、旧9画像も追加NN前の
幾何記録と同一。NNなしの実Rust selector replayは126組・81保存callbackの全RGB/寸法/本文/mean bitを
再現し、同じ2組だけを採用した。通常762件・実モデルを含む718件・example24件、fmt/差分チェックが成功し、
Clippyは既存45件から新規0件だった。証拠packetの空ディレクトリでの復元確認を続ける。

証拠packetは別の空ディレクトリで全14,839パス・正式48 CSV/Markdown・33,528 CSV行を復元/再生成し、
モデルなしで実Rust selectorを再コンパイルして126判定/81callbackの一致を確認した。初回の再実行で
Cargoの作業ディレクトリ変更による相対入力パスの不具合を検出し、元manifestを変更せず実行用コピーの
パスだけを復元先へ解決する修正をRed→Greenし、全検査をやり直した。
[全証拠と再現手順](benchmarks/vertical-capacity/README.md)を参照。30モデルの残差は多く、目的全体は継続する。
