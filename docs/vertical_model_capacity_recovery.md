# 検出された長い縦列の容量回復候補

## 幾何テスト・実装・追加NN前の仕様

実資料監査 docs/real_vertical_scan_audit.md で、同じ検出9列の30モデルに大きいraw欠落があった。
PageRecognizerのDEIM経路へまだ変更を加えず、まず既存の分割/支持を利用できるかをtest-onlyで
検査する。原文・book/PID/font・文字列置換を選択条件へ渡さない。

### 原画素と支持用mask

- Autoが既に回転する極端な縦長cropだけを対象にする。原cropを既存の無補間90度回転へ渡す。
  これは元Auto入力と同じ画素順であり、方向推定の新しい条件を導入しない。
- 画素補間・色補正・モデル変更をNN入力へ加えない。支持用の同寸法maskには既存の
  normalize_chromatic_panelsを使い、色の付いた紙が固定閾値の白帯を塞ぐかを検査する。
  NNへ渡すchunkは常に元の回転RGBから同じ座標で切り抜く。maskのRGBを認識へ渡さない。
- 分割には既存split_rotated_vertical_column_for_inputを使う。数字の内部白帯の保護と、
  縦列に単語間ASCII空白を追加しない規則を維持する。失敗や不明瞭な分割は元結果へ戻す。

### 最初の候補の制限

新しい任意の閾値を実資料の誤りへ合わせる代わりに、既存dense horizontal recoveryの制限を
初期案として共有する。回転後のheight>=12、原結果<=16 scalar、モデル容量の2倍を厳密に超す幅、
インク列が全幅の1/3以上、字高支持が全高の1/2以上、支持group>=40かつ>=原結果の4倍を要求する。
これらは今回のNN対照を認識する前から存在する条件である。幾何が支持しなければ候補なしとする。
既存と共有できる集計を抽出する場合は、元の横書き経路の全挙動同一をテストする。

分割は2chunk以上。全chunkの非空本文とconfidence .9以上を要求し、合計出力scalar数が
max(元結果の2倍, group数の切上げ半分)以上で、Unicodeのis_alphanumericに該当するscalarが4種類以上ある場合だけ
回復候補とする。confidenceはscalar数で重み付けした元f32平均で、元結果を再採点して置換しない。
信頼度だけでの採用とはせず、前記の画線・容量の条件も必要とする。
先行の空白削除案の退行を踏まえ、元結果と候補のUnicode空白scalar列も完全一致を要求する。
モデル内部の空白を削って合わせず、空白が増減する候補はそのまま棄却する。追加NN前に固定する。

### Red→Greenで先行する検査

- 暖色紙/白紙の長い既知画線列、短い列、容量境界、17 scalar、39 group、不正RGB/寸法を
  小さい純粋テストで扱う。既存の二・三の内部白帯、細線だけの列や過長の連鎖も維持する。
- unsupportedでNN closureを呼ばないこと、どのchunkも元RGBの同座標とbyte一致することを
  例示/PBTで検査する。maskと元画像の取り違えを検出するテストを置く。
- 低confidence/空chunk/少なすぎる回復/空白増減/エラーは元結果を保つ。複数chunkの集約を境界テストする。
- 数値条件を追加NN前に凍結する。旧9検出列だけで実装を採用せず、既存縦横回帰・全ページ対照と、
  認識前に別途固定する追加実資料/非文字対照も揃える。モデル/方向/重複を独立標本と数えない。
- PageRecognizerへ接続する前に、実モデルRed、全入力別none/width/strict文字・単語非悪化、
  新しい未観測対照での適用、元RGB/座標の不変性を確認する。退行があれば案を棄却する。

この仕様は候補の調査であり、幾何到達性や追加認識による改善をまだ測定済みとは主張しない。
初回幾何テストで前提自体が成立しなければ、その失敗を保存し、別案として設計し直す。
